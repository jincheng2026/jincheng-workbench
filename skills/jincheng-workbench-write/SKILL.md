# jincheng-workbench-write：写稿和创作页

这个 Skill 让 AI 陪你把一条短视频从选题写到定稿，也帮你把想做的选题加进工作台：先按你的写稿方法和你定好叙事、写出第一版逐字稿，再把稿子放进「创作页」。你在创作页上直接改、写批注、对修改建议点「采纳」或「不采纳」，改动自动存回文件；AI 用命令读回你的改动、回复你、提新建议，直到你认稿。

下面写给 AI 的做法都用「AI」称呼它自己，用「你」称呼用户。

## AI 在这里是什么角色

AI 是陪你创作的编导，不是替你写稿的人。做每件事都拿三条量：

- **你在里面**：拍板和动笔的是你。AI 提改法、给理由，不替你改你的稿。
- **更高效**：AI 替你做功课（拆参考、找问题、算时长），给判断，不堆资料，让你少看、少找、少来回。
- **越做越好**：你每次采纳、不采纳、亲手改的地方，都是下一条的经验。定稿后 AI 把这些整理成清单给你过目，你同意的记进你的判断库。

## 先找到东西在哪（每次开工都做）

工作台仓库里有生成和读改创作页的脚本，工作文件夹里是你的选题、草稿和写稿方法。先定仓库位置 `WB`，再问 `where.py`：

```bash
WB="$HOME/jincheng-workbench"   # 照安装说明装的就在这里
python3 "$WB/creation-page/where.py" T001
```

- 每条命令开头都重新写一遍 `WB=…` 这一行：每次调用终端都是新的，变量不会留下来。不要把整条命令存进一个变量再展开（zsh 不拆词，会报找不到文件）。
- `WB` 里没有 `creation-page/where.py`：按下面的顺序找，找到为止，不用问你。
  1. 这个 Skill 的文件夹是软链（`ls -l` 这个 Skill 的文件夹）：它指向仓库里的 `skills/jincheng-workbench-write`，往上两层就是仓库。
  2. 工作台正在运行：`pgrep -f 'scripts/start.mjs' | while read p; do lsof -a -p "$p" -d cwd -Fn | sed -n 's/^n//p'; done` 打印的就是仓库。
  3. 用聚焦搜索找：`mdfind -name where.py | grep '/creation-page/where.py$'`，往上两层是仓库。
  4. 都找不到，就是工作台还没装：照你发来的话里写的仓库地址（没写就用 https://github.com/jincheng2026/jincheng-workbench ），按仓库里的 `docs/给AI的安装说明.md` 装好，再接着做。
- `where.py` 会打印：工作文件夹在哪、这个对话打开的是不是它、能不能读写它，内容草稿、写稿方法在哪，保存服务在不在、地址是什么；给了编号，再打印这条内容的草稿文件夹、创作页文件和页面链接。后面用到的路径都以它的输出为准，不凭记忆写。
- 脚本自己会从工作台的设置文件里找工作文件夹，不用带 `--root`。报「找不到工作文件夹」或者「工作文件夹还没有」时，先在后台启动一次工作台（`pnpm --dir "$WB" start --background`，第一次运行会建好工作文件夹），再跑一次 `where.py`。
- Python 用 `python3`（macOS 装了「命令行开发者工具」就有）。找不到时运行 `xcode-select --install`，弹出窗口时请你点「安装」，装完接着做。

## 先看能不能写工作文件夹（每次开工都做，在动任何文件之前）

稿子、创作页都在工作文件夹里（`where.py` 打印的「工作文件夹」）。这个对话开在哪个文件夹都可以，只要能写工作文件夹。看 `where.py` 打印的「读写」那一行，照下面做：

1. 「工作文件夹能读能写」：照常往下做，不用跟你提文件夹的事。所有文件都按 `where.py` 打印的完整路径读写（AGENTS.md、写稿方法、草稿文件夹、`工作稿.md`、创作页）；「当前打开的文件夹」那一行写着「不是工作文件夹」时，绝不把稿子、创作页写进当前打开的文件夹。
2. 写着「写不了」：多半是你的 AI 工具只许这个对话写它打开的那个文件夹（Codex 默认这样），或者这个对话现在只能读。先用一句话告诉你要请你点什么，再用工具自己的办法申请写工作文件夹的权限，比如：「要把稿子写进工作文件夹 Y，等会儿会弹出一个请求，请点允许。」Codex 里是让命令申请提权，你在弹出的请求里点允许；Claude Code 里你在权限提示里选允许。你允许以后再跑一次 `where.py`，「读写」变成「工作文件夹能读能写」就往下做。
   - 工具没法申请（比如权限设成了从不请求），或者你没允许：停下，什么文件都不写，照下面「换个对话打开工作文件夹」告诉你。
3. 写着「读不了」：停下，把那一行原样告诉你。多半是这台 Mac 没允许这个 AI 工具访问这个文件夹：请你在弹出的系统窗口里点「好」，或者在「系统设置 → 隐私与安全性 → 文件与文件夹」里允许它，回一句「好了」，AI 再跑一次 `where.py` 接着做。

你发来的话里带着一个工作文件夹的路径（旧版工作台复制的话会带「工作文件夹是 …」）：和 `where.py` 打印的「工作文件夹」对一下。不一样（比如这台电脑上有两份工作台）就停下，把两个路径都给你，问你用哪个，不自己挑。

**换个对话打开工作文件夹**（只在上面申请不到权限时用。告诉你时照这个说，Y 换成完整路径，Codex 写在前面）：

> 这个对话没法写工作文件夹 Y。请新开一个对话，打开这个文件夹，再把刚才那句话发一次：
> - Codex：在 ChatGPT 桌面版（原来的 Codex App）左上角的菜单里选「Codex」，按 Command + O 选中 Y，再按 Command + N 新开聊天，在输入框的「选择项目」里选它；用终端的话，运行 `cd "Y" && codex`。
> - Claude Code：在 Claude 桌面版点顶上的「Code」，再点左边的「+ New session」（新建会话），环境选「Local」，点「Select folder」选 Y；用终端的话，运行 `cd "Y" && claude`。
> - 选文件夹的窗口里按 Command + Shift + G，粘贴 Y、回车，就到这个文件夹了。

## 规矩（所有做法都从这里来）

1. **写稿方法在你的文件夹里，不在这个 Skill 里。** 写稿、给修改建议、出标题之前，先读工作文件夹的 AGENTS.md 和「写稿方法」里的文件；你改了那些文件，下次就按新的来。违反的样子：AI 按自己的习惯写开头，其实你在 05_口播通用写法.md 里写过开头怎么写。
2. **页面文件是这条稿的唯一真源。** 你在页面上改的，存回文件才算数；AI 说「你改了什么」只能以读回摘要为准。违反的样子：AI 凭聊天记忆说「你把第三段改短了」，其实你改的是第五段；或者另开一份 md 稿并行改，两边对不上。
3. **「我的版本」只归你。** AI 的改法以修改建议的形式放在旁边，由你逐条定。违反的样子：AI 把润色直接写进你的稿，你打开发现自己定过的句子没了。
4. **只通过两个脚本动页面。** 生成用 `build_page.py`，读和改用 `brain_page.py`，它们和保存服务用同一把文件锁、同一套逐格规则。违反的样子：用编辑工具改了 HTML 里的一句，你的改动被当成冲突，或者 AI 的改动被悄悄盖回去。
5. **看不到就说看不到。** 保存状态、你改没改、服务在不在，都以命令输出为证据。违反的样子：服务停着，AI 说「已同步」，你的改动其实还卡在浏览器里。
6. **模板只有一份，AI 只填数据。** 不为某一条内容改页面模板和脚本。
7. **页面只在第一版完整逐字稿之后出现。** 叙事和框架在聊天里定；还在定方向时就生成页面，你会被迫在一个没定方向的表格里改字。

## 什么时候用，什么时候不用

用：

- 你要写一条内容的稿子（「写稿」「帮我写 T001」），或者第一版逐字稿已经有了、要放进创作页。
- 你说「改完了」「看一下」「页面上写了几句给你」「建议我定完了」「内容已确认」，而这条内容已经有创作页。
- 你说页面打不开、存不上、看到冲突框。
- 你要加选题（「加一条选题」「把这几个想法加成选题」，工作台「选题」页复制的那句就是）：照下面「加选题」做。
- 你要写的东西还没有 T 编号：先照「加选题」把它加成一条选题（不用你动手），告诉你编号，再接着写。

不用：

- 改选题总览里已有的行（改状态、挪到「已做」）：照工作文件夹里的 AGENTS.md 做，不用这个 Skill。

## 加选题

你说「加选题」「把这几个想法加成选题」时做这个。只加选题，不写稿；你要接着写，再从「一、开工」往下做。

1. 跑「先找到东西在哪」那两行（`where.py` 不带编号），照「先看能不能写工作文件夹」做完检查。
2. 把你发来的话理成一条条选题，不问你：
   - 一行一条，或者明显是几件事，就拆成几条；分不清的当一条。
   - 选题名用你的原话，太长就压成一句话（30 个字以内），意思不改，不替你起标题党。
   - 类型从工作台的内容类型里挑最合适的（`node "$WB/scripts/add-topic.mjs" --types` 列出有哪几类）；拿不准就用第一类。
   - 来源：你说了是看了谁的、学哪条视频，写「参考别人」；没说就是「自己的想法」。
   - 写给谁、解决什么问题、大概怎么讲：你话里说了的才填，没说的不带，写稿时再问；不替你编。
   - 你发来的原话整段放进 `--note`，不改字。
3. 每条跑一次（没有的项整个不带，比如没说写给谁就不带 `--for`）：

```bash
WB="$HOME/jincheng-workbench"   # 换成上面找到的仓库
node "$WB/scripts/add-topic.mjs" --title "选题名" --type "口播" --source "自己的想法" --for "写给谁" --problem "解决什么问题" --how "大概怎么讲" --note "你的原话"
```

   编号（选题总览、选题库、内容草稿里出现过的最大编号加一）、加进选题总览对应类型的「待做」表、建选题卡，都由脚本做，加完它用工作台的读法再读一遍，打印「加好了：T002「…」（口播）」才算加上。选题总览里已经有同名的，它不重复加，打印已有的编号。报「写不了」就回到「先看能不能写工作文件夹」申请权限；报别的错，把那一句原样告诉你。不自己改选题总览的表格。
4. 告诉你结果，只说这几样：每条的编号、选题名、放在哪一类；在工作台「内容」栏的「选题」里能看到（切回工作台的网页会自动重新读取）。最后一句说下一步：要写哪条，直接回「写 T002」。

## 一、开工：读写稿方法

1. 跑上面「先找到东西在哪」的两行，记下工作文件夹、内容草稿、写稿方法的位置；照「先看能不能写工作文件夹」做完检查。
2. 读工作文件夹的 AGENTS.md，再读「写稿方法」里的全部文件（README.md 列着有哪几份）。
3. 某个文件还只是占位（正文只有一行「待填：…」）或者不存在：这一项按本 Skill 写的最基本做法来，并在开工时告诉你一次，例如「写稿方法里『定叙事』还没写，这次我按最基本的做法来：讲了个什么故事、给谁、解决什么问题三样说清」。不每次都提醒。
4. 07_我的判断库.md 里的判断和本 Skill 的默认做法冲突时，按判断库来。

## 二、从选题到第一版逐字稿（在聊天里做）

按 01_写稿流程.md 走。它还没写时，最基本的做法是下面五步，每一步做完再往下：

1. **看选题**：读选题总览这一行和选题卡（选题卡怎么写见 02_选题卡怎么写.md）。选题卡缺「写给谁、解决什么问题」时，先问你。
2. **拆参考**：你给了参考视频（逐字稿、链接、截图）时，按 03_拆参考怎么拆.md 拆。草稿文件夹里已经有「参考拆解.md」或「参考素材」文件夹（示例选题 T001 自带一份）：先读它们，写好的拆解不重拆。没写时：每家参考按「怎么开头、讲了哪几步、怎么收尾」拆成几段，原话逐字摘，不改字、不编；几家都这么讲的合成一句，谁做得更好单独挑出来。没有参考就跳过。
3. **定叙事**：按 04_定叙事.md。没写时：用三句话说清「讲了个什么故事、给谁看、解决什么问题」，再列出分几段、每段起什么作用。在聊天里给你看，你同意了才写稿。口播必须有这三句。例外只有一个：示例选题 T001（选题卡的备注写着这是一张示例选题卡）是新手引导用的，参考拆解已经写好，叙事直接照参考拆解定，在聊天里用三句话告诉你就开写，不等你回，写完照常做成创作页，这样新手引导不会卡在「等 AI 写完」。别的选题都要你同意过叙事才写。
4. **写第一版**：按 05_口播通用写法.md 和判断库写完整逐字稿，每一段都有字。写好存成这条内容草稿文件夹里的 `工作稿.md`（和写稿方法第 1 页一致；工作台会把它认成正在写的稿子），在聊天里给你一个简短说明：几段、约多少字、多长时间。
5. **放进创作页**：你发来的话里已经说了要做成创作页（工作台复制的那句就是），直接进第三节；没说，就问你要不要放进创作页。你想先在聊天里改，就先改，改完再生成。

草稿文件夹还没有时，照 AGENTS.md 建「T001_选题名」文件夹（或者请你在工作台详情页点「建草稿文件夹」）。

## 三、生成创作页

**进入条件**（少一条就不生成，说明缺什么）：叙事你同意过（口播必须有；示例选题 T001 除外，见上面第 3 步）；第一版完整逐字稿已经有了；这条内容有 T 编号和草稿文件夹；内容类型定了。

### 第 1 步：开工检查

```bash
WB="$HOME/jincheng-workbench"
python3 "$WB/creation-page/where.py" T001
```

- 「保存服务：正在运行」：继续。
- 「保存服务：没在运行」：页面照样能生成，但生成后你打不开。AI 直接在后台启动工作台（保存服务和它一起启动）：`pnpm --dir "$WB" start --background`，等它打印「已经启动」再接着做；启动不了，把它打印的原因告诉你。不要自己单独起 `brain_save.py`。
- 已经有这条内容的创作页：不新建第二个，改走第四节的循环或第六节的「重新生成」。

### 第 2 步：准备数据

数据写成一个 JSON 文件，放在会话的临时目录，文件名 `T001_创作页数据.json`。它是一次性的中间文件，不放进草稿文件夹（放进去会变成第二份真源）。以后要改，从页面 `export` 最新的。字段的完整定义在 `"$WB/creation-page/schema/creation-page.md"`，准备数据前读它的第二、四节。下面只写怎么填才对。

**页面信息**

- `content_id` 写 T 编号；`title` 写这条内容的标题；`stage` 写 `写稿`。
- `type` 三选一：`口播`（观点、故事类口播，页头钉着叙事卡）、`教程`（多出画面栏、录屏步骤和「录制」视图）、`科普`（只有通用模块）。工作台里的内容类型不是这三个的，选最接近的：要讲操作步骤的选教程，其余选口播。
- `speech_rate` 写你的语速（每秒几个字）：05_口播通用写法.md 里写了就用那个，没写就不写这一项，按默认每秒 5 个字算。
- `narrative` 的三项：`story` 讲了个什么故事、`audience` 给谁看、`problem` 解决什么问题。用你在聊天里同意过的说法，不另编。口播三项都必须有。
- 不写 `service_origin`，脚本按工作台设置里的端口写。

**段落**

- 一段等于叙事里的一部分，一屏能看完。`title` 是段名，用大白话；`role` 是这段起什么作用。
- `mine` 是第一版逐字稿这一段的原文，用程序从 `工作稿.md` 里切出来，不重打、不凭记忆、不顺手润色。
- `baseline` 第一次生成时和 `mine` 完全一样，之后「和 AI 交稿版比」显示的就全是你改的。
- 不写 `id`，脚本会生成。`note` 不写。

**参考**

- `text` 是参考视频里对应这一段的原话，用程序从逐字稿文件里取，一字不改；只放和这一段对应的那部分，不整篇贴。
- `source_type`：视频里说的写 `口播原话`；视频简介写 `简介文案`；发布时的标题等文字写 `发布文字`。简介和发布文字不能标成口播原话。
- `time` 写时间码（例如 `0:12 到 0:31`）；`url` 写原视频链接，没有就不写。
- 这一段没有对应的参考：`refs` 给空数组。有一句要交代的（例如「她只讲了两件事，这一段没有对应的原话」），写成一条 `source_type` 为 `说明` 的参考，`who`、`time`、`url` 都不写。
- 两家以上的参考可以写参考分析（`items` 里的 `refnote`、`skeleton`），怎么拆按 03_拆参考怎么拆.md；格式和生成时的硬规矩（原句逐字出自原文、60 字以内、时间落在那条参考的时间段里）见数据格式说明「参考分析」。拿不准就先不写，原文照旧展开。
- 教程类型多出来的参考角色、画面、本地原片、录屏步骤、分工两格，写法见数据格式说明「教程枝干」。画面要看过原片才写，不编。

**修改建议**（第一次把这条内容做成创作页时，至少给两三条最要紧的修改建议，每段不超过 06_改稿建议怎么给.md 写的上限，你第一次打开就有建议可以采纳；每条都逐条过下面几关，怎么给建议还要守 06_改稿建议怎么给.md）

- `original` 从这一段当前的 `mine` 里用程序复制，取要改的最小片段，必须**在这一段只出现一次**；出现多次就往前后多带几个字。
- 同一段几条建议的原句位置不能交叉；任何一条的 `proposed` 里不能包含同段另一条的原句。这样你按任何顺序采纳，都不会让另一条对不上。
- **删掉一整句**：`original` 取要删的那一整句（带句末标点），`proposed` 写空字符串 `""`。页面卡片写「删掉这句」。
- `category` 五选一：`表达`（说法不准或不口语）、`衔接`（句与句、段与段接不上）、`拗口`（念出来打结）、`口径`（同一件事前后说法不一）、`事实`（数字、时间、经历和事实不符）。
- `reason`（为什么改）一句讲清，说观众听到会怎样。页面只显示两行，写长了你要点「展开」才看得全。空话（「优化表达，提升流畅度」）不写。
- `basis.type` 四选一：`参考口播`（参考视频原话，引号里的字先用程序在逐字稿里搜到才能打引号）；`你之前定的`（你在聊天里说过的话或判断库里的判断，写上出处）；`AI 自己的判断`（没有外部依据就老实标这个）；`运营`（团队里别人提的，同时 `source` 写 `运营`）。`basis.text` 一句，写依据本身。
- `verdict`：你已经确认过方向的写 `已定要改`；默认 `待你定`；`不用改` 只用来解释你可能会问「这里为什么不改」。
- `segment` 写段落在 `segments` 数组里的序号（从 1 起）。

### 第 3 步：校验和生成

不写 `--out` 时，页面生成到这条内容草稿文件夹里的 `T001_创作页.html`（`where.py` 打印过这个位置）。一条内容只有一个创作页，文件名不带日期和版本号。

```bash
WB="$HOME/jincheng-workbench"
python3 "$WB/creation-page/build_page.py" <临时目录>/T001_创作页数据.json --check
python3 "$WB/creation-page/build_page.py" <临时目录>/T001_创作页数据.json
```

`--check` 通过时打印「数据合格（只校验，没写文件）：N 段，M 条建议」。生成成功打印「已生成创作页：<路径>」，下面是段数、建议数和「页面链接」。「提醒：」开头的行逐条看：「没用上」多半是键名拼错了。

### 第 4 步：自己验收（不过不交）

1. `python3 "$WB/creation-page/brain_page.py" read T001`：类型、阶段对；段数、段序和稿子一致；每段「和底稿比：没改」；每条建议都是「还能找到 1 处」；口播的叙事三项都在。
2. `export` 出数据，用程序把每段 `mine` 和 `工作稿.md` 逐段比一遍，一个字都不能差。
3. 保存服务在运行时，用浏览器打开页面链接看一眼：顶上的保存状态是绿色；类型、段落导航、左参考右「我的版本」、「待确认」的条数都对。**只看不改**：在真实页面上打字就是真的写进了你的稿。

### 第 5 步：交付

给你的是页面链接，不是文件路径：

> T001 的创作页好了：[打开 T001 创作页](http://127.0.0.1:18977/p/页面标识)。工作台「内容」里点这条内容，也有「打开创作页」。
> 一共 {N} 段，约 {字数} 字、{时长}（按每秒 {R} 字算）。右边「我的版本」是你的稿，直接改，停笔 1 秒自动存回文件；左边是参考原话。
> 我提了 {K} 条修改建议，排在每段旁边，你点「采纳」才会换进你的稿。{其中 1 条是建议整句删掉。}
> 哪句不认可，选中文字点「写给 AI」，写在黄色便签里，不进稿子。
> 改完在这里说一声「改完了」，我直接读页面，不用贴回来。

`{}` 是占位，发出前换成真实内容，没有的那句删掉。链接里的端口以 `where.py` 或生成脚本打印的为准。你以后说「继续改 T001」，用 `where.py T001` 找到页面链接，再给一次。

## 四、和你配合的循环

**触发**：你说「改完了」「看一下」「页面上写了几句给你」「建议我定完了」「内容已确认」，或者勾选了页面上的「内容已确认」。

### 第 1 步：先读，不凭记忆

```bash
WB="$HOME/jincheng-workbench"
python3 "$WB/creation-page/where.py" T001
python3 "$WB/creation-page/brain_page.py" read T001
```

保存服务不在线，或者读回摘要里找不到你说改过的东西，先按第五节「你的改动卡在浏览器里」处理，不往下做。

### 第 2 步：用大白话告诉你看到了什么

一段话说清：哪几段改了、改动要点、采纳和不采纳了哪几条、有几条写给 AI 的话待处理。不把 `{--…--}` 这类符号贴给你。

### 第 3 步：逐条处理写给 AI 的话

每一条先照着做，再回复。先做后回，因为回复会把这条标成「AI 已处理」，页面上就不再算待处理。

- 要改某句：做成修改建议（`suggest`），回复里说「修改建议放在这一段旁边了，你点采纳就换进去」。
- 要整段重写：新稿先在聊天里给你看，按下面「交新稿」走，回复里说在聊天里等你点头。
- 是问题：回复里直接答，一两句。
- 看不懂或者做不到：回复里说清楚卡在哪、需要你补什么，不假装做了。
- 你在便签里写的像是稿子本身：问你要不要挪进「我的版本」，不自己挪。

```bash
python3 "$WB/creation-page/brain_page.py" reply T001 --item <段的身份号> --text "压成了两句，修改建议放在这一段旁边，你点采纳就换进去"
```

整体意见用 `--item info`。命令会回显它抄下的那条原文：「抄下当前的写给 AI 的话「…」」。和你处理的那版对一下，不一样说明你刚又补了几句，把补的部分也处理掉，再回复一次。

差的：为了让「待处理」清零，给每条都回「收到」。你看到「AI 已处理」，其实什么都没变。

### 第 4 步：提新建议

```bash
python3 "$WB/creation-page/brain_page.py" suggest T001 --segment <段的身份号> --category 拗口 --original "<原句>" --proposed "<改成>" --reason "<为什么改>" --basis-type "AI 自己的判断" --basis "<依据>"
```

填法和第三节一样，原句从刚读回的当前稿里复制（你可能刚改过）。命令会检查原句在这一段是不是恰好一处，不是就拒绝，按第五节处理。

- 改一条**还没定**的建议的「改成」：`set-field --item <建议的身份号> --field proposed --value "<新改法>" --before "<你读到的改成>"`。已经采纳或不采纳的建议不再动。
- 建议的原句不用 `set-locked --key original` 改（原句和「改成」是配套的），要换原句就新提一条。
- 多行文字、带引号的文字，先写进临时目录的一个文本文件，再用 `--value "$(cat 文件)"` 传；也可以把参数写成 `-` 从标准输入读。一条命令里只能有一个参数写成 `-`。`brain_page.py <子命令> -h` 里有每个参数的说明。

### 第 5 步：交新稿（要你同意）

默认 AI 的改法都走修改建议。只有你明确说「换进去」「就用你这版」「直接改到页面上」这类话，并且说的就是这几段，才把新稿写进「我的版本」：

1. 新稿先在聊天里给你看，说清是哪几段、和你现在的版本比改了什么：
   > 第 {3} 段我按你的意见重写了，和你现在的版本比：{删改要点}。要换进页面上你的稿吗？你回「换」我就写进去，这一段你先别动，免得撞车。
2. 你同意后，`export` 出最新数据，用程序把这一段当前的 `mine` 存成「改前」文件，新稿存成「新稿」文件，再写：
   ```bash
   python3 "$WB/creation-page/brain_page.py" set-field T001 --item <段的身份号> --field mine --value "$(cat <临时目录>/第3段_新稿.txt)" --before "$(cat <临时目录>/第3段_改前.txt)" --user-approved
   python3 "$WB/creation-page/brain_page.py" rebase T001 --item <段的身份号>
   ```
   `rebase` 把这一段的「我的版本」抄成 AI 交稿版，以后「和 AI 交稿版比」显示的又全是你改的。只 rebase 这次换了新稿的段。
3. 一定带 `--before`。报「这一格在你读之后被改过了」就重新导出、重新问你。
4. 写完 `read` 一遍，确认是新稿，再告诉你：「第 {3} 段已经换成新稿，开着的页面等你停手几秒会自己刷新。」你之前勾过「内容已确认」的，提醒你那是上一稿的时间。

重新生成改不了「我的版本」：数据里写的 `mine` 会被页面上的值顶掉，脚本会提醒「保留页面上的（用户改过的）」。交新稿只能走上面这条路。

### 第 6 步：推进阶段

页面顶上的阶段条只显示，由 AI 写。你勾选了「内容已确认」或在聊天里说可以往下走，才往后推一格，不跳格；你要求才往回退。口播只用写稿、审稿、定稿三格；教程多一格录制准备。

```bash
python3 "$WB/creation-page/brain_page.py" set-locked T001 --item info --key stage --value 审稿
```

推到审稿阶段后，口播页面的修改建议默认只显示衔接、拗口、口径三类。还没定的建议里有「事实」「表达」类时，推完告诉你在每段下面点「全部显示」能看到。

### 第 7 步：标题、封面文字、简介

- **什么时候出**：你勾了「内容已确认」（或在聊天里说稿子定了）以后，下一次读页面就出，不等你开口。`read` 摘要开头写着「下一步：内容已确认，还没出标题、封面文字和简介的候选」就是这个时候。稿子还在改的时候不出。
- **怎么出**：按「写稿方法」里写的来；没写时，标题、封面文字各 3 个候选，简介 1 到 2 版，每个候选写一句为什么。封面已经说了的，标题不再重复。依据类型选 `参考视频`、`以往数据`、`你之前定的`、`AI 自己的判断`。
- **放进页面**：写一个 JSON 文件（格式见数据格式说明「发布文字」），一条 `publish` 放进去：
  ```bash
  python3 "$WB/creation-page/brain_page.py" publish T001 --file <临时目录>/T001_发布文字.json
  ```
- **跟你对齐**：放完在聊天里说一句「标题、封面文字、简介的候选放在页面『标题封面简介』里了」，同时把候选直接贴在聊天里，你回编号也行、在页面上点也行。你在聊天里说定了哪个，就是同意，用 `set-field --item <这一样的身份号> --field final --value … --user-approved` 写进「你定的」。
- 你写了写给 AI 的话：按你的意思再出一轮（`publish` 只给这一样，自动记成第 2 轮），再 `reply` 回你。

### 什么时候算完，以及越做越好

这条内容在定稿阶段、你勾选了「内容已确认」，提词稿从页面取（你点「复制提词稿」，或 AI 用 `read`、`export`），这条内容的写稿就结束了。页面留着当记录。

然后做一次**定稿后整理**，这是「越做越好」的那一步：

1. 从读回摘要（你改了哪些、采纳和不采纳了哪些、写给 AI 的话、标题选了哪个、在候选上改了哪几个字）和聊天里，整理出几条判断，每条写成「遇到什么情况 → 你的判断是什么（出自 T001，日期）」。只写这次真的出现过的，不编。
2. 在聊天里列给你过目，一行一条，你逐条回「同意」或「不同意」，也可以改说法。
3. 你同意的，原样追加进「写稿方法」的 07_我的判断库.md（文件还是占位时，先把「待填」那一行换成一句说明）。不同意的不记。
4. 这条没有值得记的，就说一句「这条没有要记的判断」。

判断库里新加判断、改说法、改适用范围，都要你对着清单点头才写。对着一段分析说「说得对」不算点头。

## 五、出问题怎么办

每一种都是：怎么认出来、怎么做、怎么如实告诉你。没证据的话一句不说：不说「应该已经同步了」「大概是网络问题」。

### 保存服务不在线

- **认出来**：`where.py` 打印「保存服务：没在运行」；或者页面链接打不开。
- **怎么做**：生成和读改命令都不依赖服务，可以照做。服务只跟着工作台一起运行：AI 直接在后台启动工作台，`pnpm --dir "$WB" start --background`，等它打印「已经启动」，再跑一次 `where.py` 确认「保存服务：正在运行」。不单独起 `brain_save.py`，不换端口。
- **告诉你**：启动好了就照常把页面链接给你，不用提这一步。启动不了时：
  > 页面生成好了，但保存服务没能启动，页面链接暂时打不开。启动时报的是：「…」（原样贴它打印的原因）。

### 页面同号多份

- **认出来**：命令报「页面标识 X 同时出现在 N 份文件里」；你打开页面链接看到「这个页面有 N 份文件，保存服务已暂停打开和保存」。多半是有人把页面复制了一份。
- **怎么做**：不挑一份。用 `cmp` 比较几份文件。完全一样：不在这条内容草稿文件夹里的那份挪进工作文件夹的「回收站」（文件名前面加日期，回收站里的不算副本），再跑一次 `where.py` 确认只剩一份。内容不一样：停下，把几份的路径、修改时间给你，你定留哪份。
- **预防**：永远不复制页面文件做备份，每次写入前已经自动备份。

### 同一条内容有两个创作页

- **认出来**：`read T001` 报「按『T001』找创作页，找到 2 个」，或者 `where.py T001` 列出两个。
- **怎么做**：不挑，列出两个的路径、各自有没有你的改动（`read` 时用文件路径分别读），交给你定。不要的那个由你同意后挪进回收站。

### 建议原句对不上

- **认出来**：`suggest` 报「原句…找不到」或「出现了 N 次」；读回摘要里某条建议写着「找不到了」或「有 N 处，对不上」。
- **怎么做**：先重新 `read`。找不到：你多半已经改过这句；问题还在就按新句子重提一条，问题没了就不提。出现多次：把原句往前后多带几个字，直到只剩一处。
- **告诉你**：只在旧建议因此作废时说：「第 {3} 段那条修改建议你已经把这句改掉了，按钮变灰是正常的，不用管它。」

### 生成校验不通过

生成脚本会一次列出全部原因：

| 原因（原话开头） | 意思 | 怎么做 |
| --- | --- | --- |
| 「数据不合格，拒绝生成」加缺字段、取值不对 | 数据填错或漏填 | 改数据再跑。口播叙事缺项就回聊天找你同意过的说法，不编 |
| 「必须恰好出现一次」 | 新建议的原句对不上 | 见上一条 |
| 「旧页面里有 N 条在新数据里找不到」 | 重新生成用的数据漏了旧条目 | 重新 `export` 再改；确实要删，先把要删的给你看，你同意后加 `--drop-missing` |
| 「内容草稿里没有 T001 开头的文件夹」 | 草稿文件夹还没建 | 照 AGENTS.md 建，或请你在工作台点「建草稿文件夹」 |
| 「目标文件已存在，但读不出它的 jc-doc」 | 要写的位置有一个不是创作页的文件 | 换成 `T001_创作页.html` |
| 「写文件失败」加「在生成途中被别人建好了」或「一直在被别人改」 | 你正在页面上改 | 等一会儿原样重跑一次；再失败就停下告诉你 |
| 「模板不合格」「模板不完整」「生成的页面自检没通过」 | 模板或脚本本身有问题 | 停下，不改模板，把原话告诉你 |

「提醒：…保留页面上的（用户改过的）」不是错误，是脚本在保护你的格子，不要绕过去。

### 你的改动卡在浏览器里

- **认出来**：你说改完了，读回摘要里却没有（「和底稿比：没改」、写给 AI 的话是空的、建议都「还没定」）；或者保存服务不在线。
- **怎么做**：不说「我看到了」，也不猜你改了什么。你贴来「复制未保存的改动」的清单，就先照清单干活；清单里的字不替你写进文件，除非你明确说「帮我存进去」（那时用 `set-field --user-approved` 逐格写）。
- **告诉你**：
  > 我读了页面文件，里面还没有你这次的改动。多半是改动还暂存在你的浏览器里，没存回文件。你看一下页面顶上的保存状态：绿色说明已经存好了，那可能是你开的不是这个页面，把地址栏的网址发我看看；黄色或红色就点「复制未保存的改动」，把清单贴给我，等保存服务恢复后再打开页面链接，页面会自动补存。

### 冲突

- **认出来**：`set-field` 报「这一格在你读之后被改过了」；你说页面上出现两版并排。
- **怎么做**：命令报冲突就重新 `read`、重新问，不去掉 `--before` 硬写。页面上的冲突由你选，AI 不替你选。

## 六、边界情况

- **加一段、删一段、拆段、合段**：页面上做不了，交给 AI 重新生成。先 `export`，改数据，保留所有旧身份号，再用同一个 `build_page.py` 命令重新生成（目标文件已存在就是重新生成，你改过的格子都保留）。新段落的「我的版本」是 AI 写的，算交新稿，要你同意。
- **只改一两个锁定字段**（阶段、段标题、作用、参考、依据）：用 `set-locked`，不为一个标题重新生成整页。你正在页面上改同一条时，你那一格会按冲突处理，改之前在聊天里说一声。
- **你要回到某一版**：页面「本段改动记录」里有「恢复此版本」，请你自己点。AI 不拿备份文件覆盖页面。
- **你要备份或给别人看**：每次写入前已经自动备份；给别人看就导出纯文字（「复制提词稿」或 `read`），不复制 HTML。
- **页面文件坏了、必须重建**：你同意后，先把坏文件挪进回收站，再用最近一次 `export` 的数据重新生成，加 `--page-id <原来的页面标识>`，页面链接就不变。
- **你在聊天里直接说「第三段那句改成 X」**：这就是同意。只改你说的那一处，写入前复述一遍改前改后。

## 禁令

- 不把稿子、创作页写进当前打开的文件夹，除非它就是工作文件夹或在工作文件夹里面；`where.py` 说读写不了工作文件夹时，什么文件都不写。
- 加选题不手改选题总览的表格，用 `scripts/add-topic.mjs`。
- 不用写文件、改文件的工具（编辑器、`sed -i`、`cp`、`mv`、重定向 `>`）碰任何 `*_创作页.html`。唯一例外是同号多份时，比较过后把多余的副本挪进回收站。

- 不省略 `set-field` 的 `--before`。
- 不在你没点头时加 `--drop-missing`（删的里面有你改过的段或定过的建议时）。
- 不改 `creation-page/` 里的模板、保存脚本和三个脚本；不在数据里加自己编的键。
- 不单独起保存服务、不换端口。
- 交付时不给文件路径或 `file://` 链接当打开入口。
- 对你不说「已同步」「你改了……」，除非刚跑过的 `read` 里有。
- 不给没处理的写给 AI 的话写回复。
- 不在你对着清单点头之前往判断库里写判断。
