# 数据格式

调研 Skill 写进工作文件夹的东西长什么样。工作台「市场调研」页读的就是这些文件；字段是两边约定好的，改之前先改这份说明和工作台那边。

## 文件夹

```
<工作文件夹>/市场调研/              （三个子文件夹的位置分别在工作台设置的 paths.benchmarkAccounts、researchReports、commentImports 里改，默认都在「市场调研」下）
├── 对标账号/
│   └── <平台>-<账号名>/          比如「抖音-示例博主小林」
│       ├── 档案.json
│       ├── 作品.json             用 TikHub 拉过才有
│       ├── 头像.jpg               扩展名按图片实际格式：jpg、png、webp……
│       ├── 主页截图-1.png         手动建档时用户给的截图
│       └── 代表作封面-1.jpg       TikHub 拉的是互动最多的三条；手动建档时是用户给的
├── 调研报告/
│   └── <日期_主题>/              比如「2026-10-03_AI会议纪要教程评论区」
│       ├── meta.json
│       ├── 评论洞察.html / 账号研究.html / 视频拆解.html
│       └── 生成报告用的数据：评论数据.json、分析.json、账号数据.json、拆解.json、逐字稿.txt
├── 评论导入/                      社媒助手导出的评论表（Excel、CSV、TSV、JSON 都行）
└── .tikhub/                       以点开头，工作台不显示
    ├── 用量.jsonl                 每次请求一行：时间、接口、状态、按官方单价算的花费（不记密钥、参数和返回内容）
    ├── 缓存/                      24 小时内同样的请求直接用这里的，不重复花钱
    └── 原始返回/                  解析不出来的返回存这里，方便排查（不含密钥）
```

平台名用中文：抖音、小红书、视频号、B站、快手、TikTok、YouTube、微博、其他。文件夹名里的 `/ \ : * ? " < > |` 换成空格。

## 档案.json

```json
{
  "platform": "抖音",
  "account_name": "示例博主小林",
  "url": "https://www.douyin.com/user/MS4wLjABAAAAfakeuser01",
  "note": "开头抓人，想学他的开头",
  "tags": ["AI办公", "教程"],
  "updated_at": "2026-10-03T15:04:05+08:00",
  "followers": 12800,
  "bio": "每天一个 AI 小技巧",
  "source": "tikhub"
}
```

| 字段 | 必有 | 说明 |
| --- | --- | --- |
| platform | 是 | 中文平台名 |
| account_name | 是 | 账号名 |
| url | 是 | 主页链接；手动建档没给链接时是空字符串 |
| note | 是 | 用户写的备注（为什么对标他），没有就是空字符串 |
| tags | 是 | 文字数组，可以是空数组 |
| updated_at | 是 | 最后一次更新的时间，带时区 |
| followers | 否 | 粉丝数，整数；读不出来就不写 |
| bio | 否 | 简介 |
| source | 否 | `tikhub`（用 TikHub 拉的）或 `manual`（手动建的） |

不写这些以外的键。同一个主页链接再拉一次，只更新资料；note 和 tags 这次没给新的就保留。`python3 research.py account list` 会核对每个档案。

## 作品.json

```json
{
  "platform": "抖音",
  "account_name": "示例博主小林",
  "url": "https://www.douyin.com/user/…",
  "fetched_at": "2026-10-03T15:04:05+08:00",
  "source": "tikhub",
  "followers": 12800,
  "works_total": 32,
  "likes_total": 256000,
  "works": [
    {"id": "7400000000000000101", "url": "https://www.douyin.com/video/7400000000000000101", "title": "…", "desc": "作品文案原文",
     "published_at": "2026-09-30 08:00", "duration_seconds": 46.0, "type": "视频", "likes": 637, "comments": 31, "collects": 133,
     "shares": 21, "pinned": false, "tags": ["AI工具"], "cover": "代表作封面-1.jpg", "cover_url": "https://…（这条的封面图链接）"}
  ]
}
```

数字读不到就是 `null`，不当成 0。下载下来的代表作封面写在 `cover`。`cover_url` 是这条作品的封面图链接，封面 Skill 拆封面 VI 时照它下载最近的封面；链接带签名、过几天会过期，过期了用 `account add` 重新拉一次。头像链接不存。

## meta.json（每个报告文件夹一份）

```json
{
  "title": "会议纪要教程的评论区：录音导入和收费最让人卡住",
  "date": "2026-10-03",
  "type": "评论洞察",
  "source": "导入的表格：市场调研/评论导入/xxx.xlsx · https://www.douyin.com/video/…",
  "pages": [{"file": "评论洞察.html", "title": "评论洞察"}],
  "workbenchVisible": true
}
```

- `type` 只有三种：评论洞察、视频拆解、账号研究。
- `date` 取文件夹名开头的日期。`pages` 第一项是主报告。`source` 只给人看，说数据从哪来。
- 文件夹里还没有 HTML（比如评论整理好了、分析还没写），工作台不显示它。

## 评论数据.json

`comments prepare` 或 `comments fetch` 写的，是一条视频（或几条）评论清洗以后的样子：

- `source`：`kind` 是「导入的表格」（带 `file`、`format`）或「TikHub」（带 `collected_at`、`requests`、`cost_usd`）。
- `videos`：每条视频的编号、链接、标题、平台显示的评论总数、这次几条、有效几条。
- `columns`：认出的列（要的东西 ← 表头）、认得但没用的列（评论者编号、主页这类个人信息）、认不出的列。
- `stats`：原始行数、重复、没法分析的条数和原因、有效条数、一级和回复各多少、点赞合计、评论时间范围。
- `comments`：一条一个，`ref` 是短号（c1、c2……），另有 `text`、`likes`、`time`、`ip`、`level`（一级、回复、未知）、`parent_ref`（回复的是哪条）、`by_author`（作者本人）、`noise`（没法分析的原因，正常评论是 null）。不存评论者的昵称、编号和主页。

## 分析.json

评论洞察的写法和格式见 `评论洞察怎么做.md`。账号研究的是：

```json
{"summary": "一句话", "observations": [{"title": "…", "text": "…", "works": ["作品编号"]}]}
```

## 拆解 JSON（`video render --data`）

```json
{
  "title": "拆解：某博主的三分钟写周报",
  "summary": "一句话：这条最值得学的是什么",
  "video": {"platform": "抖音", "url": "…", "author": "…", "published_at": "2026-09-30 08:00", "duration_seconds": 52,
            "likes": 5230, "comments": 260, "collects": 2400, "shares": 380, "desc": "作品文案原文", "source": "tikhub"},
  "sections": [
    {"title": "开头怎么抓人", "text": "…", "quotes": ["逐字稿里的原话"]}
  ],
  "transcript_source": "用户贴的逐字稿"
}
```

`video` 里的字段可以直接用 `video fetch --out 文件` 存下来的；`sections` 按写稿方法里 `03_拆参考怎么拆.md` 的几件事写。给了 `--transcript`，`quotes` 里每句都要能在逐字稿里找到（标点、空格不算）。
