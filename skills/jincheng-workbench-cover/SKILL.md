# jincheng-workbench-cover：拆封面 VI、出一批封面、按评论改一张、定下用哪张

这个 Skill 让 AI 替你做封面。工作台管拆封面、管风格和封面 VI；出图、挑、改在 Codex 桌面版里做。

先把你想学的封面拆成一套能照着做的规律（封面 VI）：可以是一个对标博主最近的 20 张封面，也可以是你拖进工作台「封面」页的几张图。再拿你放在「人物参考图片」里的照片和这套规律，给一条选题一次出一批构图各不相同的封面，竖版 3:4、横版 2.35:1、方形 1:1 都行，存图时从中间裁好。用 Codex 桌面版的话，出来的图就在对话里：点开切到 Canvas 一起看，哪张想改，用 Comment 在图上标出来写句话，AI 只改你标的地方，存成新的一张；定了用哪张跟它说一声。工作台里这条选题的页面也能看到每一批。

下面写给 AI 的做法都用「AI」称呼它自己，用「你」称呼用户。

## AI 在这里是什么角色

AI 是替你出封面的美术助理，交出来的东西要能直接挑、直接用。做每件事都拿三条量：

- **你在里面**：学谁、挑哪张、改哪里，你定。AI 不替你挑；一批里生成坏了的也照样留着，写清问题。挑和改用 Codex 自带的看图和评论：你在图上标、AI 只改你标的地方。
- **更高效**：一批里每张构图都不一样，每张的自检写成一句话，你在 Canvas 里一眼就能比；你只写一句评论，AI 只改那一处。
- **说得出依据**：拆 VI 时每条规律都能点到原图编号；每张封面都写得出照的是哪张原图、保留了哪几个关系。

## 先找到东西在哪（每次开工都做）

脚本在工作台仓库里这个 Skill 的文件夹下。先定仓库位置 `WB`，再问 `where`（要出封面、改封面时带上内容编号）：

```bash
WB="$HOME/jincheng-workbench"   # 照安装说明装的就在这里
python3 "$WB/skills/jincheng-workbench-cover/scripts/cover.py" where T002
```

- 每条命令开头都重新写一遍 `WB=…` 这一行：每次调用终端都是新的，变量不会留下来。不要把整条命令存进一个变量再展开（zsh 不拆词，会报找不到文件）。下文的命令都省略了 `WB=` 那一行，写成 `python3 "$WB/…/cover.py"`。
- `WB` 里没有这个脚本：按下面的顺序找，找到为止，不用问你。
  1. 这个 Skill 的文件夹是软链（`ls -l` 这个 Skill 的文件夹）：它指向仓库里的 `skills/jincheng-workbench-cover`，往上两层就是仓库。
  2. 工作台正在运行：`pgrep -f 'scripts/start.mjs' | while read p; do lsof -a -p "$p" -d cwd -Fn | sed -n 's/^n//p'; done` 打印的就是仓库。
  3. 用聚焦搜索找：`mdfind -name cover.py | grep '/jincheng-workbench-cover/scripts/cover.py$'`，往上四层是仓库。
  4. 都找不到，就是工作台还没装（或者是还没有封面 Skill 的旧版本）：照你发来的话里写的仓库地址（没写就用 https://github.com/jincheng2026/jincheng-workbench ），按仓库里的 `docs/给AI的安装说明.md` 装好或更新，再接着做。
- `where` 会打印：工作文件夹在哪、这个对话打开的是不是它、能不能读写它，工作台在不在运行，「封面素材」在哪、人物参考图片（出封面用哪几张，按什么顺序）、默认风格、一批几张，全部风格（每个一行：风格编号、风格名或者「还没拆」、几张原图、默认构图、是不是默认风格）；给了编号，再打印这条内容的选题名、内容类型、草稿文件夹、封面候选里有几张、下一张的编号、现在是第几批、上一批用的尺寸、生成记录在哪、工作台里这条选题的页面。后面用到的路径都以它的输出为准，不凭记忆写。
- 打印「工作文件夹还没有」：AI 直接在后台启动一次工作台（`pnpm --dir "$WB" start --background`，第一次运行会建好工作文件夹），再跑一次 `where`。
- Python 用 `python3`，只用 Python 自带的模块，不用装任何包（装了 Pillow 时拆 VI 会多做两项检查，没装照样能做完）；裁图用 macOS 自带的 `sips`。找不到 `python3` 时运行 `xcode-select --install`，弹出窗口时请你点「安装」，装完接着做。

## 先看能不能写工作文件夹（每次开工都做，在动任何文件之前）

封面、VI 拆解、生成记录都写进工作文件夹。这个对话开在哪个文件夹都可以，只要能写工作文件夹。看 `where` 打印的「读写」那一行，照下面做：

1. 「工作文件夹能读能写」：照常往下做，不用跟你提文件夹的事。所有文件都按 `where` 打印的完整路径读写；「当前打开的文件夹」那一行写着「不是工作文件夹」时，绝不把封面、VI 拆解写进当前打开的文件夹。
2. 写着「写不了」：多半是你的 AI 工具只许这个对话写它打开的那个文件夹（Codex 默认这样），或者这个对话现在只能读。先用一句话告诉你要请你点什么，再用工具自己的办法申请写工作文件夹的权限，比如：「要把封面存进工作文件夹 Y，等会儿会弹出一个请求，请点允许。」Codex 里是让命令申请提权，你在弹出的请求里点允许；Claude Code 里你在权限提示里选允许。你允许以后再跑一次 `where`，「读写」变成「工作文件夹能读能写」就往下做。
   - 工具没法申请（比如权限设成了从不请求），或者你没允许：停下，什么文件都不写，照下面「换个对话打开工作文件夹」告诉你。
3. 写着「读不了」：停下，把那一行原样告诉你。多半是这台 Mac 没允许这个 AI 工具访问这个文件夹：请你在弹出的系统窗口里点「好」，或者在「系统设置 → 隐私与安全性 → 文件与文件夹」里允许它，回一句「好了」，AI 再跑一次 `where` 接着做。

你发来的话里带着一个工作文件夹的路径：和 `where` 打印的「工作文件夹」对一下。不一样（比如这台电脑上有两份工作台）就停下，把两个路径都给你，问你用哪个，不自己挑。

**换个对话打开工作文件夹**（只在上面申请不到权限时用。告诉你时照这个说，Y 换成完整路径，Codex 写在前面）：

> 这个对话没法写工作文件夹 Y。请新开一个对话，打开这个文件夹，再把刚才那句话发一次：
> - Codex：在 ChatGPT 桌面版（原来的 Codex App）左上角的菜单里选「Codex」，按 Command + O 选中 Y，再按 Command + N 新开聊天，在输入框的「选择项目」里选它；用终端的话，运行 `cd "Y" && codex`。
> - Claude Code：在 Claude 桌面版点顶上的「Code」，再点左边的「+ New session」（新建会话），环境选「Local」，点「Select folder」选 Y；用终端的话，运行 `cd "Y" && claude`。
> - 选文件夹的窗口里按 Command + Shift + G，粘贴 Y、回车，就到这个文件夹了。

## 规矩（所有做法都从这里来）

1. **你挑，AI 不挑。** 一批全部留给你挑：你在对话里说用哪张，AI 才跑 `select`。违反的样子：AI 觉得 05 最好，把它复制成了 `封面-选定.png`。
2. **只写看到的。** VI 规律从原图里看，每条能点到原图编号；不写作者的官方规范，不用播放量证明效果。违反的样子：没打开 K07，就在观察里写「K07 也是左右对比」。
3. **你的脸只用你的照片。** 原图只做构图和美术方向参考，提示词写明把图里的人换成你，不混脸、不继承对方的发型衣服；你的几张照片都是你本人，只当长相参考。违反的样子：出来的人一半像你、一半像对标博主。
4. **封面上的字一字不改。** 字词、大小写、数字、标点都不变，只能改换行、位置、大小。违反的样子：为了排版好看，把「十分钟」改成「10 分钟」，或者加一句「建议收藏」。
5. **文件只增不改。** 候选永远用新编号，不覆盖、不删；你的照片、原图不动（只有 `style split` 会把几张原图挪进新的风格文件夹、名字改回原名）；生成记录、默认构图、封面设置只用命令写。违反的样子：重做 03 时直接盖掉了原来的 `封面-03.png`，你想对比也找不回来了。
6. **尺寸照这批定的。** 生图按这个尺寸的画面大小出，存图时 `save --size` 从中间裁好；字和脸都放在裁完还在的那块里。违反的样子：横版 2.35:1 的封面把标题写在最上面，裁完只剩半行字。
7. **看不到就说看不到。** 生成成没成、存没存、裁没裁、工作台在不在，都以命令输出为证据。违反的样子：生图工具报错了，AI 还说「5 张都出好了」。

## 先认清是 Codex 还是 Claude Code（出图之前）

你用的是哪个 AI 工具，AI 自己知道，按自己是哪个做：

- **Codex**：用 Codex 自带的生图（image_gen）一张一张直接出图，开一批时写 `--tool image_gen`。每张生成后跑 `save`：它从 Codex 的生图文件夹（`$CODEX_HOME/generated_images/`，没设 `CODEX_HOME` 就是 `~/.codex/generated_images/`）里拿最新的那张，从中间裁成这批的尺寸，存成 `封面候选/封面-NN.png`。
  - 这个 Codex 里没有 image_gen（版本旧或者没开）：照下面 Claude Code 的做法只出提示词，交付时多说一句「这个 Codex 现在不能直接出图」。
- **Claude Code**：没有自带的生图，开一批时写 `--tool 只出提示词`。每张照样写完整的生图提示词，存成 `生图描述-NN.md`，登记进生成记录（自检写「只出了提示词」，文件名写 `生图描述-NN.md`），交付时照下面的话说清怎么拿去生成。不自己去找别的生图服务或插件。

## 一、拆封面 VI

**什么时候**（三种来源，做法一样，都照下面第 1 到第 6 步）：

- **拆一个对标账号**：你说「拆封面 VI」「拆一下这个博主的封面」「拆对标账号某某的封面 VI」；工作台对标账号卡片、「封面」页风格卡片上复制的那句（带着账号名和平台）；「封面」页贴了博主主页链接的那句（「博主的主页链接：…」，或者最后「博主的主页链接贴在这句后面：」后面贴着）。看他最近 20 张封面。
- **拆你放进来的图**：「封面」页拖完图以后复制的那句（「拆我放进工作台「封面」里的那组图（风格/2026-10-04_8张，8 张）……」），或者你说「拆我刚放进去的那几张」。不是同一种风格就分开拆、各起名字（第 3 步）。
- **一次拆几个对标账号**：「封面」页「一次全拆」复制的那句（「把我还没拆封面 VI 的 3 个对标账号都拆了：「A」（抖音）、「B」（小红书）……」），或者你说「把还没拆的对标账号都拆了」。先读这一节最后的「一次拆几个对标账号」，再一个一个照第 1 到第 6 步拆。

### 第 1 步：认出拆哪个风格

- 话里写了风格编号（「风格/2026-10-04_8张」）：就是它。
- 话里写的是对标账号（「某某」（抖音））：在 `where` 的「风格」里找来源写着「对标账号」的「抖音-某某」，这就是它的风格编号（「<平台>-<账号名>」）。
- 贴的是主页链接：在对标账号里找这个链接（每个账号文件夹的 `档案.json` 里有 url）。找不到，先用调研 Skill 把他加进对标账号（`research.py account add "<主页链接>" --max 20`，拉他最近 20 条作品，花钱的规矩照调研 Skill），再接着做。
- 贴的是一个文件夹：
  - 就是某个对标账号的文件夹（或者它的 `封面/`）：就是那个账号。
  - 别处的文件夹（一个博主的封面）：先用调研 Skill 手动建档（`research.py account add --manual --platform <看得出是哪个平台就写哪个，看不出写「其他」> --name "<博主名，话里没说就用文件夹名>"`），下一步用 `--from` 把图复制进来。原文件夹不动。
- 话里说「放进工作台「封面」里的那组图」却没写编号：`where`「风格」里来源写着「放进来的图」、还没拆的只有一组，就是它；有几组就问你一句是哪组（这是唯一要问的）。

下面命令里的 `<风格编号>` 都写这个，带上引号。

### 第 2 步：补封面、整理文件

```bash
python3 "$WB/skills/jincheng-workbench-cover/scripts/cover.py" vi prepare "<风格编号>"
python3 "$WB/skills/jincheng-workbench-cover/scripts/cover.py" vi prepare "<风格编号>" --from "<封面所在的文件夹>"   # 封面在别处时
```

- 它做的事：把 `封面/` 里不叫 K01 这种名字的图按顺序改名（对标账号知道发布时间的从新到旧，别的按文件名顺序），新旧名字写进 `封面/原文件名.md`，图不删；最后生成研究清单。对标账号的 `作品.json` 里有封面链接、`封面/` 又不够 20 张时，先按发布时间从新到旧下载最近的，下过的不重下；给了 `--from` 就把那个文件夹里的图复制进 `封面/`。

### 第 3 步：逐张看图，写观察

先读 `references/observation.md`。先总览一遍，知道有哪几种构图；再把研究范围内每一张用看图的工具在能看清细节的尺寸打开（`封面/K01.jpg`……），每张都要真的打开看，缩略图看过不算。

- **默认构图**：AI 从案例和选图建议里挑 5 张最能代表这个风格、彼此构图又明显不一样的原图，按推荐的先后写进 `--compositions`（原图不到 5 张就有几张写几张）。不写就按 `study.json` 里案例的顺序取前 5 个。它存进风格文件夹的 `默认构图.json`，编号要是这个风格 `封面/` 里真有的图；你在工作台改过的（`where` 里写着「你改过的」）不覆盖。
- 导出后通读一遍 `VI拆解.md`：表格里每行是不是这张图的事，选图建议有没有把「适合什么选题」写清。有问题改 `study.json` 再导出，不手改 `VI拆解.md`。

### 第 2 步：读话里的这几样

### 第 4 步：写生成计划

张数：话里说了几张就几张，没说用 `where` 打印的「一批几张」。

- 任意两张至少在主要道具、动作、视角、空间、文字布局里有两项看得出的区别。不固定「几种构图乘几张」，不用换背景色充数。

### 第 5 步：一张一张生成

每张按 `references/生成方法.md` 的骨架写完整提示词：前几张输入图是你的照片（`record batch` 打印的，按那个顺序，最多 3 张，都是你的长相参考），最后一张是这张选的构图原图（只做构图和美术方向参考，提示词写明把图里的人换成你）。提示词写明最终比例和安全区。人物、字、道具、环境在同一次生成里一起出，不先出背景再贴人。

- 提示词存成 `封面候选/生图描述-NN.md`：开头几行写每张输入图的完整路径（「输入图 1（长相参考）：…」……最后「输入图 4（构图参考 K03）：…」）和尺寸（「尺寸：横版 2.35:1，生图出 1536×1024，存的时候从中间裁成 1536×654」），下面是能直接复制去用的整段提示词。
- 你的照片是 heic：先用 `sips -s format jpeg <照片> --out <会话的临时目录>/照片.jpg` 转一份 jpg 再交给生图，转出来的不放进工作文件夹。
- **Codex**：image_gen 生成这一张，画面大小选这个尺寸的生图尺寸（竖版 1024×1536、横版 1536×1024、方形 1024×1024；工具不能选就在提示词里写明），然后：
  ```bash
  python3 "$WB/skills/jincheng-workbench-cover/scripts/cover.py" save T002 --no 03 --size 竖版3:4 --keep 上
  python3 "$WB/skills/jincheng-workbench-cover/scripts/cover.py" record add T002 --no 03 --change "K03 讲台：人在右后，前景放大的手机" --check "通过" --file 封面-03.png
  ```
  - `save` 之前先看刚生成的这张原图，定从哪里裁（`--keep`）：标题、脸靠近上边（常见），写 `--keep 上`，从上边开始留、多裁下面；脚、手、字靠近下边写 `--keep 下`；上下都留得有空用默认的「中」；拿不准就写从上边第几像素开始留（比如 `--keep 40`）。2026-10-04 真跑时生图把标题放在离顶边约 56 像素的地方，从中间裁会切掉上面约 85 像素，标题就被切了一截。
  - `save` 用 macOS 自带的 `sips` 裁好再存，打印裁之前、裁之后的大小和上下各裁掉几像素；没裁的原图留在 Codex 的生图文件夹里，不放进工作文件夹。
  - `save` 之后打开存进封面候选的这张（裁好的那张）看：字、脸、手被切到了，换个 `--keep` 加 `--replace` 再存一次（只有还没登记的这张能重存），再看，都完整了再按 `references/验收.md` 自检、登记。自检写的是裁好以后的样子；只有裁成什么样都切到字的，才在自检里写问题。
  - 登记完在对话里紧跟着这张图写一行「封面-03：K03 讲台，人在右后；自检：通过」：你在 Codex 里点开图、切到 Canvas 看这一批时，每张都对得上编号。
- **Claude Code**：写好生图描述就登记：
  ```bash

  ```
  你在别处生成好图交回来（拖进对话，或者告诉 AI 在哪）：AI 先把拖进来的存成文件，看一眼定从哪里裁，再 `save T002 --no 03 --from "<图>" --size 竖版3:4 --keep 上`（存成同一个编号，裁好），看过以后 `record add T002 --no 03 … --file 封面-03.png`（把只出了提示词的那一行换成这张），都放进来以后再跑一次 `record summary`。
- 编号从 `record batch` 打印的那个开始往后排，一张一个。
- 「本张变化」写成「原图编号 一句话画面」。用了文字回退（见 `生成方法.md`）的，在这句末尾写「（参考方式：文字回退）」。
- 自检一句话、30 字以内、先写结论：全过写「通过」；有问题只写问题本身，比如「头发遮住「AI」的 A」「三只手」「标题被裁掉一截」。检查过程不写进这一句，你看这一批时对照的就是它。
- 先看最早出来的 2 到 3 张，确认没有混脸、错字、空间变平、字和脸被裁掉，再接着出整组；有混脸就改用文字回退接着出，不停下来等你。
- 一批里不逐张重做：某张不合格照样存、照样登记，自检写问题，接着出下一张。生图工具连续 3 次报错才停，把报错原样告诉你（多半是额度或者服务出了问题）。

## 三、按你的评论改一张

**什么时候**：

- 你在 Codex 里点开图、在 Canvas 里用「Comment」在一张或几张图上标了要改的地方，勾上它们连同要求发来（Codex 桌面版自带的看图、评论、改图，官方说明见 learn.chatgpt.com/docs/image-generation）；
- 你在对话里说「把 03 的字改大一点」「07 换个姿势」。

1. 跑 `where T002`，照第二件事第 1 步看读写、人物参考图片、工作台。
2. 认出改的是哪几张：Canvas 发来的图，按出图时你在每张下面写的「封面-03：……」那一行对上编号；对不上就问一句是哪张（这是唯一要问的）。勾了几张就一张一张改，每张改出一张新的。
3. 看清要改什么：评论逐条读。评论的标记只用来看改哪里，不交给生图（会被画进新图）。
4. 找到原来那张的生图描述（`生图描述-03.md`）和它照的构图原图（生成记录里这张「本张变化」开头的 K 编号，在那一批第一行的风格里），还有这张的尺寸（生成记录里它那一批第一行的「尺寸」）；把这次的改法写成新编号的生图描述（新编号是 `where` 打印的「下一张的编号」）：说到的地方怎么改，没说到的（脸、封面上的字、构图、配色、尺寸）都写明不变。
5. 生成：
   - **Codex，原图就在这个对话里**（Canvas 发来的，或者这一批就是在这个对话里出的）：在原图上直接改，只改说到的地方，别的照原样；改到脸的，把你的照片一起给它当长相参考。改出来糊了、脸不像了、或者构图跑了，就退回下面全新生成那一种再出一次。
   - **原图不在这个对话里**（新开的对话）：全新生成一次，你的照片加那张构图原图，配上改好的提示词，不在别的对话的图上接着改，这样改出来的图不糊。

## 出问题怎么办

每一种都照脚本打印的原话告诉你，再说下一步。不说「应该是网络问题」这类没证据的话。

| 脚本说 | 意思 | 怎么做 |
| --- | --- | --- |
| 「工作文件夹还没有」 | 工作台还没运行过 | 在后台启动一次工作台，再跑 `where` |
| 「工作台的设置文件写坏了」「封面设置写坏了」 | JSON 坏了 | 把那句话原样告诉你；你同意的话照它说的改好，或者在工作台里重新设一次 |
| 「认不出风格……」 | 风格编号写错了，或者对标账号还没建档 | 照 `where`「风格」里的写法改；是新博主就照第一件事第 1 步，先用调研 Skill 建档 |
| 「还没有能拆的封面」「还没有能拆的图」 | 拿不到原图 | 对标账号照第一件事第 2 步先用 TikHub 拉、拉不了请你放；你放进来的图请你在「封面」页重新拖一次 |
| 「下载封面时连不上网」 | 多半是 AI 工具的沙箱不让命令联网 | 用能联网的权限再跑一次 `vi prepare`（Codex 里让这条命令申请提权，先跟你说一句等会儿点允许） |
| 「有 N 张下载失败」「作品.json 里没有封面链接」 | 封面链接过期了，或者作品数据是旧版调研 Skill 拉的 | 够 10 张照常拆；不够的照第一件事第 2 步，先用 TikHub 重新拉，拉不了再请你放 |
| 「研究数据还要改」（`vi check`、`vi build`） | 研究数据不合格 | 照它说的改 `study.json` 再跑，不删依据来凑过 |
| 「封面整理得不对」（`vi inventory`） | 有图打不开、编号重复 | 照它说的处理那几张图，再从 `vi prepare` 跑起 |
| 「封面/ 里没有 K09」 | 默认构图、参考构图或者要分出去的编号不在这个风格里 | 照它列的范围改编号；话里的编号对不上就回去对一下风格编号 |
| 「对标账号不拆分文件夹」「不能全挪走」「先跑 vi prepare」（`style split`） | 分风格只对你放进来的图，要留下一部分，图要先编号 | 照它说的做；对标账号有两种风格的写进 VI拆解 |
| 「还没有默认风格」「还没有人物参考图片」「还没拆封面 VI」 | 缺前提 | 照第二件事第 1 步 |
| 「尺寸只能写……」 | 尺寸写错了 | 写 `竖版3:4`、`横版2.35:1`、`方形1:1` 之一 |
| 「这台电脑上找不到 sips」「用 sips 裁图没成功」「裁出来是……」 | 裁不了图 | 把那句话原样告诉你；这张先不存，不说「存好了」 |
| 「这张是 …的方图，… 要的是 …」（`save` 存好以后提醒） | 生出来的画面方向不对，裁掉了不少 | 打开存好的那张看字和脸还在不在，自检写上；不行就照那个大小重新生成 |
| 「Codex 的生图文件夹里没有图」「最新的一张是 N 分钟以前的」 | 这张多半没生成出来 | 确认生成成功了再 `save`；图存在别处就用 `--from` |
| 「这张图已经存过了」 | 拿到的还是上一张 | 同上 |
| 「编号已经用过了」「已经登记过了」 | 编号不复用 | 用它说的下一个编号 |
| 「封面候选里还没有 封面-NN」 | 先登记了、图还没存 | 先 `save` 再 `record add` |
| 「封面候选里没有 封面-NN 的图」（`select`） | 这张还没有图，或者编号说错了 | 只出了提示词的，等图放进来再选；编号拿不准就问你 |
| 「自检要一句话、30 字以内」 | 写长了 | 只留结论 |
| 「工作台：查不了」 | AI 工具的沙箱不让连本机端口 | 用能连本机端口的权限再跑一次 `where`（Codex 里让这条命令申请提权） |
| 「封面脚本出错了，这是程序的问题」 | 脚本有 bug | 把输出原样告诉你，不自己改脚本绕过去 |

## 禁令

- 不把封面、VI 拆解写进当前打开的文件夹，除非它就是工作文件夹或在工作文件夹里面；`where` 说读写不了工作文件夹时，什么文件都不写。
- 不手改生成记录的表格和批次小节，用 `record batch`、`record add`、`record summary`；「## 记录」也只用 `record note` 加（选定由 `select` 记）。不手改封面设置，用 `settings`；不手改 `默认构图.json`、`风格.json`，默认构图用 `vi export --compositions` 写，你在工作台改。
- 不覆盖、不删、不改名任何候选、生图描述、你的照片、原图；编号不复用。分风格只用 `style split`，只对你放进来的图。
- 不替你挑：你没说用哪张，就不跑 `select`。
- 不改封面上的字；不加副标题、英文、账号名。没有真实数据不画图表、不写百分比、不做像真的软件后台。
- 每张只拿你的照片做身份（最多 3 张，都是你本人）；原图只做构图参考，提示词写明换成你、不混脸；出现混脸就改用文字回退。
- 字和脸不放在会被裁掉的地方；不跳过 `save --size` 直接把没裁的图放进封面候选。
- 人物要和画面有动作关系：指、托、拿、按、看、操作；不把人贴在空角落。
- 不把别人的脸、文案、商标、产品数据当成可以照搬的东西写进 VI 的「保留关系」；保留的是空间、体量、字形、材质、动作关系。
- 对标账号的封面原图和你放进来的图，只在你自己的电脑上研究、当构图参考，不发到网上，不放进要公开的地方。
- 不手改 `VI拆解.md`、报告网页和清单：要改就改 `study.json`，再导出、再出报告。
- 不问风格名，不问要不要设成默认风格：风格名 AI 自己起；还没有默认风格就设成默认，交付时告诉你在哪里改。
- Claude Code 里不自己找别的生图服务或插件。
- 对你不说「存好了」「出好了」「裁好了」，除非刚跑过的 `save`、`record` 输出里有。
