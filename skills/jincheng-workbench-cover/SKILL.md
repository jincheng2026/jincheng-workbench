# jincheng-workbench-cover：拆封面 VI、出一批封面、按备注改一张

这个 Skill 让 AI 替你做视频封面：先把一个你想学的博主的封面拆成一套能照着做的规律（封面 VI），再拿你的照片和这套规律，给一条选题一次出一批构图各不相同的 3:4 封面，你在工作台详情页挑一张；哪张想改，在图上点一下写句备注，AI 只改你说的地方，存成新的一张。

下面写给 AI 的做法都用「AI」称呼它自己，用「你」称呼用户。

## AI 在这里是什么角色

AI 是替你出封面的美术助理，交出来的东西要能直接挑、直接用。做每件事都拿三条量：

- **你在里面**：学谁、挑哪张、改哪里，你定。AI 不替你挑；一批里生成坏了的也照样留着，写清问题。
- **更高效**：一批里每张构图都不一样，每张的自检写成一句话，你在详情页一眼就能比；你只写一句备注，AI 只改那一处。
- **说得出依据**：拆 VI 时每条规律都能点到原图编号；每张封面都写得出照的是哪张原图、保留了哪几个关系。

## 先找到东西在哪（每次开工都做）

脚本在工作台仓库里这个 Skill 的文件夹下。先定仓库位置 `WB`，再问 `where`（要出封面、改封面时带上内容编号）：

```bash
WB="$HOME/jincheng-workbench"   # 照安装说明装的就在这里
python3 "$WB/skills/jincheng-workbench-cover/scripts/cover.py" where T002
```

- 每条命令开头都重新写一遍 `WB=…` 这一行：每次调用终端都是新的，变量不会留下来。不要把整条命令存进一个变量再展开（zsh 不拆词，会报找不到文件）。下文的命令都省略了 `WB=` 那一行，写成 `python3 "$WB/…/cover.py"`。
- `WB` 里没有这个脚本：按下面的顺序找，找到为止，不用问你。
  1. 这个 Skill 的文件夹是软链（`ls -l` 这个 Skill 的文件夹）：它指向仓库里的 `skills/jincheng-workbench-cover`，往上两层就是仓库。
  2. 工作台正在运行：`pgrep -f 'scripts/start.mjs' | while read p; do lsof -a -p "$p" -d cwd -Fn | sed -n 's/^n//p'; done` 打印的就是仓库。
  3. 用聚焦搜索找：`mdfind -name cover.py | grep '/jincheng-workbench-cover/scripts/cover.py$'`，往上四层是仓库。
  4. 都找不到，就是工作台还没装（或者是还没有封面 Skill 的旧版本）：照你发来的话里写的仓库地址（没写就用 https://github.com/jincheng2026/jincheng-workbench ），按仓库里的 `docs/给AI的安装说明.md` 装好或更新，再接着做。
- `where` 会打印：工作文件夹在哪、这个对话打开的是不是它、能不能读写它，工作台在不在运行，「封面素材」在哪、你的照片和默认对标设没设、一批几张，哪些对标账号拆过封面 VI；给了编号，再打印这条内容的选题名、草稿文件夹、封面候选里有几张、下一张的编号、现在是第几批、生成记录在哪、工作台详情页的链接。后面用到的路径都以它的输出为准，不凭记忆写。
- 打印「工作文件夹还没有」：AI 直接在后台启动一次工作台（`pnpm --dir "$WB" start --background`，第一次运行会建好工作文件夹），再跑一次 `where`。
- Python 用 `python3`，只用 Python 自带的模块，不用装任何包（装了 Pillow 时拆 VI 会多做两项检查，没装照样能做完）。找不到 `python3` 时运行 `xcode-select --install`，弹出窗口时请你点「安装」，装完接着做。

## 先看能不能写工作文件夹（每次开工都做，在动任何文件之前）

封面、VI 拆解、生成记录都写进工作文件夹。这个对话开在哪个文件夹都可以，只要能写工作文件夹。看 `where` 打印的「读写」那一行，照下面做：

1. 「工作文件夹能读能写」：照常往下做，不用跟你提文件夹的事。所有文件都按 `where` 打印的完整路径读写；「当前打开的文件夹」那一行写着「不是工作文件夹」时，绝不把封面、VI 拆解写进当前打开的文件夹。
2. 写着「写不了」：多半是你的 AI 工具只许这个对话写它打开的那个文件夹（Codex 默认这样），或者这个对话现在只能读。先用一句话告诉你要请你点什么，再用工具自己的办法申请写工作文件夹的权限，比如：「要把封面存进工作文件夹 Y，等会儿会弹出一个请求，请点允许。」Codex 里是让命令申请提权，你在弹出的请求里点允许；Claude Code 里你在权限提示里选允许。你允许以后再跑一次 `where`，「读写」变成「工作文件夹能读能写」就往下做。
   - 工具没法申请（比如权限设成了从不请求），或者你没允许：停下，什么文件都不写，照下面「换个对话打开工作文件夹」告诉你。
3. 写着「读不了」：停下，把那一行原样告诉你。多半是这台 Mac 没允许这个 AI 工具访问这个文件夹：请你在弹出的系统窗口里点「好」，或者在「系统设置 → 隐私与安全性 → 文件与文件夹」里允许它，回一句「好了」，AI 再跑一次 `where` 接着做。

你发来的话里带着一个工作文件夹的路径：和 `where` 打印的「工作文件夹」对一下。不一样（比如这台电脑上有两份工作台）就停下，把两个路径都给你，问你用哪个，不自己挑。

**换个对话打开工作文件夹**（只在上面申请不到权限时用。告诉你时照这个说，Y 换成完整路径，Codex 写在前面）：

> 这个对话没法写工作文件夹 Y。请新开一个对话，打开这个文件夹，再把刚才那句话发一次：
> - Codex：在 ChatGPT 桌面版（原来的 Codex App）左上角的菜单里选「Codex」，按 Command + O 选中 Y，再按 Command + N 新开聊天，在输入框的「选择项目」里选它；用终端的话，运行 `cd "Y" && codex`。
> - Claude Code：在 Claude 桌面版点顶上的「Code」，再点左边的「+ New session」（新建会话），环境选「Local」，点「Select folder」选 Y；用终端的话，运行 `cd "Y" && claude`。
> - 选文件夹的窗口里按 Command + Shift + G，粘贴 Y、回车，就到这个文件夹了。

## 规矩（所有做法都从这里来）

1. **你挑，AI 不挑。** 一批全部留给你在详情页挑；选定、收藏、删除都是你在工作台上点的。违反的样子：AI 觉得 05 最好，把它复制成了 `封面-选定.png`。
2. **只写看到的。** VI 规律从原图里看，每条能点到原图编号；不写作者的官方规范，不用播放量证明效果。违反的样子：没打开 K07，就在观察里写「K07 也是左右对比」。
3. **你的脸只用你的照片。** 对标原图只做构图和美术方向参考，提示词写明把图里的人换成你，不混脸、不继承对方的发型衣服。违反的样子：出来的人一半像你、一半像对标博主。
4. **封面上的字一字不改。** 字词、大小写、数字、标点都不变，只能改换行、位置、大小。违反的样子：为了排版好看，把「十分钟」改成「10 分钟」，或者加一句「建议收藏」。
5. **文件只增不改。** 候选永远用新编号，不覆盖、不删；你的照片、对标原图、批注图不动；生成记录只用命令写。违反的样子：重做 03 时直接盖掉了原来的 `封面-03.png`，你想对比也找不回来了。
6. **看不到就说看不到。** 生成成没成、存没存、工作台在不在，都以命令输出为证据。违反的样子：生图工具报错了，AI 还说「5 张都出好了」。

## 先认清是 Codex 还是 Claude Code（出图之前）

你用的是哪个 AI 工具，AI 自己知道，按自己是哪个做：

- **Codex**：用 Codex 自带的生图（image_gen）一张一张直接出图，开一批时写 `--tool image_gen`。每张生成后跑 `save`：它从 Codex 的生图文件夹（`$CODEX_HOME/generated_images/`，没设 `CODEX_HOME` 就是 `~/.codex/generated_images/`）里拿最新的那张，存成 `封面候选/封面-NN.png`。
  - 这个 Codex 里没有 image_gen（版本旧或者没开）：照下面 Claude Code 的做法只出提示词，交付时多说一句「这个 Codex 现在不能直接出图」。
- **Claude Code**：没有自带的生图，开一批时写 `--tool 只出提示词`。每张照样写完整的生图提示词，存成 `生图描述-NN.md`，登记进生成记录（自检写「只出了提示词」，文件名写 `生图描述-NN.md`），交付时照下面的话说清怎么拿去生成。不自己去找别的生图服务或插件。

## 一、拆一个对标账号的封面 VI

**什么时候**：你说「拆封面 VI」「拆一下这个博主的封面」；工作台对标账号卡片上复制的那句（带着账号）；市场调研页上复制的那句（后面贴了主页链接，或者封面所在的文件夹）。

### 第 1 步：认出是哪个对标账号

- 话里有对标账号（「抖音-某某」）：就是它。`where` 的「对标账号」那一行写着它在哪。
- 贴的是主页链接：在对标账号里找这个链接（每个账号文件夹的 `档案.json` 里有 url）。找不到，先用调研 Skill 把他加进对标账号（`research.py account add "<主页链接>" --max 20`，拉他最近 20 条作品，花钱的规矩照调研 Skill），再接着做。
- 贴的是一个文件夹：
  - 就是某个对标账号的文件夹（或者它的 `封面/`）：就是那个账号。
  - 别处的文件夹：先用调研 Skill 手动建档（`research.py account add --manual --platform <看得出是哪个平台就写哪个，看不出写「其他」> --name "<博主名，话里没说就用文件夹名>"`），下一步用 `--from` 把图复制进来。原文件夹不动。
- 话里有几个账号：一个一个拆。

### 第 2 步：补封面、整理文件

```bash
python3 "$WB/skills/jincheng-workbench-cover/scripts/cover.py" vi prepare "<对标账号>"
python3 "$WB/skills/jincheng-workbench-cover/scripts/cover.py" vi prepare "<对标账号>" --from "<封面所在的文件夹>"   # 封面在别处时
```

- 它做的事：账号的 `作品.json` 里有封面链接、`封面/` 又不够 20 张时，按发布时间从新到旧下载最近的，下过的不重下；给了 `--from` 就把那个文件夹里的图复制进 `封面/`；然后把不叫 K01 这种名字的图按顺序改名（知道发布时间的从新到旧，不知道的按文件名顺序），新旧名字写进 `封面/原文件名.md`，图不删；最后生成研究清单。
- 报「还没有能拆的封面」，或者「下载失败」「没有封面链接」以后不到 10 张：先看能不能用 TikHub 拉。账号是抖音或小红书、`档案.json` 里有主页链接、调研 Skill 的 `where` 说读到了 TikHub 密钥，就用调研 Skill 重新拉一次他最近 20 条作品（`research.py account add "<主页链接>" --max 20`，抖音直接拉，小红书照调研 Skill 的规矩先问你），拉完马上再跑一次 `vi prepare`：封面链接过几天就会过期，要拉完马上下。
- 拉不了（别的平台，或者 TikHub 还没接），这一步要你来做。抖音、小红书的账号先告诉你：在工作台「市场调研」页接好 TikHub（约 5 分钟），我就能自己拉；不想接的话放封面也行。然后照这样告诉你（路径换成它打印的完整路径），停下等你：
  > 这个博主的封面我这边拿不到，要请你放一下：把他最近的 10 到 20 张封面图放进 {封面/ 的完整路径}（从新到旧排更好），放好回我「好了」。
  你回「好了」再跑一次 `vi prepare`。
- 打印「没纳入的」：报告网页显示不了那种格式。heic 用 macOS 自带的 `sips` 转成 jpg（`sips -s format jpeg 图.heic --out 图.jpg`），转好的放回 `封面/` 再跑一次；原来的 heic 不删。
- 不到 10 张照样拆，结论里写明张数少、规律可能不稳；只有 1 张就只做单图拆解。

然后建研究清单：

```bash
python3 "$WB/skills/jincheng-workbench-cover/scripts/cover.py" vi inventory "<对标账号>"
```

它查每张能不能打开、有没有重复，列出这次研究哪几张（默认最多 20 张）和这次研究的限制。

### 第 3 步：逐张看图，写观察

先读 `references/observation.md`。先总览一遍，知道有哪几种构图；再把研究范围内每一张用看图的工具在能看清细节的尺寸打开（`封面/K01.jpg`……），每张都要真的打开看，缩略图看过不算。

每张写七项：可见文字、主体与动作、空间关系、文字处理、色彩与材质、解释、迁移建议，外加「实际怎么看的」和「哪些局部看不清」。标题说了什么和画面真的展示了什么分开写；从照片看不出的字体名、色值、制作工具不写成事实。

写进对标账号文件夹的 `VI研究/study.json`，格式按 `references/evidence.md`。观察的 `id` 就是 `K01` 这种编号。脚本不替 AI 看图：没打开看过的图不写成看过。

### 第 4 步：归纳规则和案例

看完再归纳，不先定套路再筛图。每条规则写清适用范围、证据编号、例外编号、边界、置信度；说「经常」就给完整的统计范围、命中、未命中、不可判编号。做一次「换名字检查」：隐去博主名，结论还能不能把他和相似的博主分开；只剩「大字、真人、有冲击力」就回原图补动作、字形、空间和阅读顺序的具体关系。

案例是出封面时要照着选的：每个写为什么选它、主体对什么做什么、前后与遮挡、文字顺序、不能破坏的关系、可以替换的内容、需要的素材、适合什么选题、失败长什么样。案例数量看样本，够覆盖主要分支和反例就行。

### 第 5 步：校验、出报告、导出 VI拆解.md

```bash
python3 "$WB/skills/jincheng-workbench-cover/scripts/cover.py" vi check "<对标账号>"
python3 "$WB/skills/jincheng-workbench-cover/scripts/cover.py" vi build "<对标账号>"
python3 "$WB/skills/jincheng-workbench-cover/scripts/cover.py" vi export "<对标账号>" --style "<风格名>"
```

- `check` 不过就按它报的改 `study.json`，不绕过。
- `build` 在「市场调研/调研报告/<日期>_<账号名>封面VI/」出报告：能点规则跳原图、放大、两图对比、搜索的网页，文字版的 `VI规范.md`，工作台读的 `meta.json`。工作台「市场调研」的调研报告里能看到。同一天再出一次另起一个文件夹，不覆盖旧的。
- 风格名 AI 自己起，不问你：四到八个字，说得出画面特点，比如「暖黄手写风」。它写在 `VI拆解.md` 第二行；以后再导出不写 `--style` 就沿用。
- 导出后通读一遍 `VI拆解.md`：表格里每行是不是这张图的事，选图建议有没有把「适合什么选题」写清。有问题改 `study.json` 再导出，不手改 `VI拆解.md`。

### 第 6 步：设成默认对标（不问你）

## 二、给一条选题出一批封面

**什么时候**：你说「做封面」「出一批封面」「给 T002 出一批封面」「再来一批」；工作台详情页复制的那句（带着编号和张数）。话里没有编号又看不出是哪条，问你一句是哪条选题（这是唯一要问的）。

### 第 1 步：开工检查


### 第 2 步：定封面上的字

按这个顺序取，取到就停：你这次话里说的 → 创作页里你定了的封面文字（`where` 打印「创作页：有」时，跑 `python3 "$WB/creation-page/brain_page.py" read T002`，看「标题、封面文字、简介」那一节你定的封面文字）→ 选题名（`where` 打印的「选题名」）。

### 第 4 步：写生成计划

张数：你这次说了几张就几张（工作台详情页那句里写着），没说用 `where` 打印的「一批几张」。

读默认对标的 `VI拆解.md`（选图建议、逐图保留关系），按这次的字和选题选对标原图，再真的打开选中的原图看。每张列出：对标原图编号、准确文字、人物动作（左手一个动作、右手一个动作、眼睛看哪）、主要道具、取景与视角、空间关系（保留原图的 3 到 5 个关系）、和最相似那张的可见差别。

- 尽量每张用不同的原图；同一张原图可以发展两个确有区别的方案，但任意两张至少在主要道具、动作、视角、空间、文字布局里有两项看得出的区别。不固定「几种构图乘几张」，不用换背景色充数。

### 第 5 步：一张一张生成

每张按 `references/生成方法.md` 的骨架写完整提示词：两张输入图，图 1 是你的照片（唯一身份参考），图 2 是这张选的对标原图（只做构图和美术方向参考，提示词写明把图里的人换成图 1 的人）。人物、字、道具、环境在同一次生成里一起出，不先出背景再贴人。

- 提示词存成 `封面候选/生图描述-NN.md`：开头两行写输入图 1、输入图 2 的完整路径，下面是能直接复制去用的整段提示词。
- 你的照片是 heic：先用 `sips -s format jpeg <照片> --out <会话的临时目录>/照片.jpg` 转一份 jpg 再交给生图，转出来的不放进工作文件夹。
- **Codex**：image_gen 生成这一张，然后：

  `save` 之后先按 `references/验收.md` 看这张，再登记。
- **Claude Code**：写好生图描述就登记：

- 「本张变化」写成「对标图编号 一句话画面」。用了文字回退（见 `生成方法.md`）的，在这句末尾写「（参考方式：文字回退）」。

- 一批里不逐张重做：某张不合格照样存、照样登记，自检写问题，接着出下一张。生图工具连续 3 次报错才停，把报错原样告诉你（多半是额度或者服务出了问题）。

## 出问题怎么办

每一种都照脚本打印的原话告诉你，再说下一步。不说「应该是网络问题」这类没证据的话。

| 脚本说 | 意思 | 怎么做 |
| --- | --- | --- |
| 「工作文件夹还没有」 | 工作台还没运行过 | 在后台启动一次工作台，再跑 `where` |
| 「工作台的设置文件写坏了」「封面设置写坏了」 | JSON 坏了 | 把那句话原样告诉你；你同意的话照它说的改好，或者在工作台里重新设一次 |
| 「对标账号里没有……」 | 账号还没建档 | 照第一件事第 1 步，先用调研 Skill 建档 |
| 「还没有能拆的封面」 | 拿不到封面图 | 照第一件事第 2 步请你放封面 |
| 「下载封面时连不上网」 | 多半是 AI 工具的沙箱不让命令联网 | 用能联网的权限再跑一次 `vi prepare`（Codex 里让这条命令申请提权，先跟你说一句等会儿点允许） |
| 「有 N 张下载失败」「作品.json 里没有封面链接」 | 封面链接过期了，或者作品数据是旧版调研 Skill 拉的 | 够 10 张照常拆；不够的照第一件事第 2 步，先用 TikHub 重新拉，拉不了再请你放 |
| 「研究数据还要改」（`vi check`、`vi build`） | 研究数据不合格 | 照它说的改 `study.json` 再跑，不删依据来凑过 |
| 「封面整理得不对」（`vi inventory`） | 有图打不开、编号重复 | 照它说的处理那几张图，再从 `vi prepare` 跑起 |
| 「还没有默认对标」「还没有照片」 | 缺前提 | 照第二件事第 1 步 |
| 「Codex 的生图文件夹里没有图」「最新的一张是 N 分钟以前的」 | 这张多半没生成出来 | 确认生成成功了再 `save`；图存在别处就用 `--from` |
| 「这张图已经存过了」 | 拿到的还是上一张 | 同上 |
| 「编号已经用过了」「已经登记过了」 | 编号不复用 | 用它说的下一个编号 |
| 「封面候选里还没有 封面-NN」 | 先登记了、图还没存 | 先 `save` 再 `record add` |
| 「自检要一句话、30 字以内」 | 写长了 | 只留结论 |
| 「工作台：查不了」 | AI 工具的沙箱不让连本机端口 | 用能连本机端口的权限再跑一次 `where`（Codex 里让这条命令申请提权） |
| 「封面脚本出错了，这是程序的问题」 | 脚本有 bug | 把输出原样告诉你，不自己改脚本绕过去 |

## 禁令

- 不把封面、VI 拆解写进当前打开的文件夹，除非它就是工作文件夹或在工作文件夹里面；`where` 说读写不了工作文件夹时，什么文件都不写。
- 不手改生成记录的表格和批次小节，用 `record batch`、`record add`、`record summary`；「## 记录」也只用 `record note` 加。不手改封面设置，用 `settings`。
- 不覆盖、不删、不改名任何候选、生图描述、你的照片、对标原图、批注图；编号不复用。
- 不替你挑，不替你选定、收藏、删除（那是你在工作台上点的）。
- 不改封面上的字；不加副标题、英文、账号名。没有真实数据不画图表、不写百分比、不做像真的软件后台。
- 每张只用你的一张照片做身份；对标原图只做构图参考，提示词写明换成你、不混脸；出现混脸就改用文字回退。
- 人物要和画面有动作关系：指、托、拿、按、看、操作；不把人贴在空角落。
- 不把别人的脸、文案、商标、产品数据当成可以照搬的东西写进 VI 的「保留关系」；保留的是空间、体量、字形、材质、动作关系。
- 对标账号的封面原图只在你自己的电脑上研究、当构图参考，不发到网上，不放进要公开的地方。
- 不手改 `VI拆解.md`、报告网页和清单：要改就改 `study.json`，再导出、再出报告。
- 不问风格名，不问要不要设成默认对标：风格名 AI 自己起；还没有默认对标就设成默认，交付时告诉你在哪里改。
- Claude Code 里不自己找别的生图服务或插件。
- 对你不说「存好了」「出好了」，除非刚跑过的 `save`、`record` 输出里有。
