# 创作页文案术语表

以后给创作页加教程、科普等新枝干或改界面时，新写的界面文字（按钮、标签、状态、悬停提示、提示条、出错说明）按这张表用词，同一件事全页只用一个说法。

| 用词 | 用在哪 | 替代了哪些旧说法 |
| --- | --- | --- |
| 修改建议（上下文清楚时简称「建议」） | AI 或运营对某一句提出的改法。建议卡区块标题统一写「修改建议」；计数、悬停提示、提示条里简称「建议」 | AI 的改法、改法（界面上同一件事原来有「AI 的改法」「改法」「建议」「修改建议」四种叫法） |
| 待确认 | 建议还没有点「采纳」或「不采纳」的状态：顶栏计数「4 条待确认」、建议卡右上角状态、「只看待确认」、通读提醒、段落条悬停、提示条。标签里不带人称；为避免和它打架，结论显示词和提示条里都不再用「确认」 | 待你定、还没定、待定、定过了 |
| 已采纳 / 未采纳 / 部分采纳 | 建议有了决定以后的状态，由文件里的决定值在显示时映射而来 | 没采纳、你采纳了这条、你没采纳这条 |
| 采纳 / 不采纳 | 用户对建议的两个动作，用户自己的词，保留 | 无，原样保留 |
| 撤销 / 撤销决定 | 「撤销」是「更多」菜单里把上一步操作退回去（⌘Z）；建议卡上把决定退回「待确认」的按钮叫「撤销决定」，两者名字分开 | 撤回 |
| 取消 | 关掉还没保存的批注框；取消勾选「内容已确认」 | 撤回（指「内容已确认」时） |
| 保存 / 正在保存 / 待保存 / 已保存到文件 | 改动写进页面文件（AI 读的就是这个文件）。动作「保存」，进行中「正在保存 N 处改动…」（带省略号），排队「N 处改动待保存」（不带省略号），完成「已保存到文件 10:32」 | 写回、写回文件、写进去、存回文件、存上、补写、提交（界面上） |
| 未保存的改动 / 你的版本（未保存） | 还没保存到文件的改动（含冲突）。按钮统一叫「复制未保存的改动」；冲突框里用户那一版标「你的版本（未保存）」 | 还没写回文件的改动、没写回的改动、复制我的改动、你的版本（未采用） |
| 放弃改动 | 冲突框里丢掉用户这一版、改用文件里的版本：「放弃改动」「整组放弃改动（用文件里的）」；输入框里的冲突仍用「换回我的」「用文件里的」这一对 | 不要了、整组不要了 |
| 暂存 / 浏览器暂存 | 保存服务没连上时，改动先存在这个浏览器里，恢复后自动保存到文件。用户已见过的说法，保留 | IndexedDB、内存、暂存数据库 |
| 保存服务 | 和工作台一起运行、负责把页面改动保存到文件的程序 | 服务（单独出现时） |
| 保存服务未连接 / 保存服务已断开 / 已连接保存服务 | 保存服务的连接状态；窄屏圆点旁短字写「服务未连接」「服务已断开」 | 服务没连上、服务断开了、已连上保存服务、保存服务在线 |
| 保存被拒绝 | 保存服务不接受这次保存（例如预览模式只读），状态条全文和窄屏短字同一个说法 | 服务拒绝写入、拒绝写入 |
| 保存功能 / 保存功能启动中 | 页面里负责保存的那部分程序；还没就绪时状态条写「保存功能启动中，暂时无法编辑…」，提示条写「保存功能启动中，请稍后再试」；出错写「保存功能出错」「保存功能无法启动」 | 保存脚本、kit、还没准备好、正在启动 |
| 页面数据 | 页面文件里存全部内容的那一段 | jc-doc、jc-doc 数据块、数据块 |
| 页面标识 | 每个页面固定的一串编码，页面链接靠它找到文件；只在出错说明和悬停里出现，方便用户转告 AI | 页面身份号、身份号（给 AI 的复制清单里仍写 page_id） |
| 页面链接 | http://127.0.0.1:端口/p/页面标识 这个固定地址；按钮和状态写「改用页面链接打开」 | 服务版、服务版页面、切到服务版、跳到服务版页面 |
| 输入框 / 这处内容 | 页面上可以改、会被保存的一处。说到能打字的框用「输入框」，冲突和撤销里泛指用「这处内容」「这几处内容」；找不到位置时的兜底称呼用「这里」 | 格子、这一格、这格、字段、条目（界面上） |
| AI 交稿版 | AI 上次交稿时「我的版本」里的稿子，用来算「你改了哪些」。我的版本下方对照标题带悬停说明，改动记录里那一行的灰字也写明 | 底稿（对用户说时；AI 用的读回摘要和数据里仍叫底稿 / baseline） |
| 删去 N 字 / 新增 N 字 | 改动统计 | 删 N 字、加 N 字 |
| 查看改动 / 收起改动 | 展开或收起一版的删改对照 | 展开看删改、收起删改 |
| 恢复此版本 / 当前版本 | 改动记录里把我的版本改回某一版的按钮，以及和当前一样时的灰色按钮；提示条写「已恢复为 X 的版本」，最新一版标「（当前）」 | 用这一版、现在就是这一版、用底稿、现在就是底稿、改回、已改回、（现在） |
| 替换我的版本里的原句 | 采纳一条改写建议后的效果：卡片写「已替换我的版本里的原句」，悬停写「采纳：用这句替换我的版本里的原句」 | 换进我的版本、换进去、替换进我的版本 |
| 删掉这句 | 「改成」为空的建议（整句删除），已经是完整短语，保留 | 无，原样保留 |
| 逐条看 / 跳过这条 / 退出逐条看 | 从第一条待确认的建议开始一条一条看，采纳或不采纳以后自动跳到原文里的下一条：修改建议标题旁的按钮叫「逐条看」，进行中顶上一条写「逐条看：这一段还有 N 条待确认」，两个按钮「跳过这条」「退出逐条看」；顶栏「N 条待确认」点了也是从第一条开始逐条看 | 无（2026-10 新加） |
| 对不上了 | 原句在我的版本里已经找不到的建议，收成一行时的状态小标签；后面跟原来那句完整说法「这句你已经改过，这条建议对不上了」 | 无（2026-10 新加） |
| 展开 / 收起（建议卡） | 已采纳、未采纳、无需修改、对不上了的建议默认收成一行，点这一行或「展开」看全，看全时右上角「收起」 | 无（2026-10 新加） |
| 待 AI 处理 / AI 已处理 | 写给 AI 的话的状态，也用于顶栏第二个计数（宽屏「3 条待 AI 处理」，窄屏「待 AI 处理 3」） | 未处理、条未处理 |
| 批注 | 选中原文后在批注框里写的一条意见，保存后连同「原句：「…」」追加进这一段的「写给 AI 的话」；撤销记录里写「给第 N 段写批注「…」」 | 第 N 段写给 AI「…」（撤销记录名） |
| 结论（显示词）：需要修改 / 建议修改 / 无需修改 | 建议卡上「结论：」后面的显示文字，只在显示时由结论值（已定要改 / 待你定 / 不用改）映射；不带人称、不用「确认」 | 已定要改、待你定、不用改（数据值不改） |
| AI 建议 / 运营建议 | 建议卡上写明是谁提的，由来源值映射 | AI 提的、运营 提的 |
| 依据（显示词）：此前的决定 / AI 自行判断 | 依据小标签和展开说明里的显示文字，只在显示时映射；「参考口播」「运营」「说明」原样 | 你之前定的、AI 自己的判断（数据值不改） |
| 已锁定 | 保存功能不可用或有冲突时输入框不能编辑的状态 | 锁住了、已锁住 |
| 无法 | 做不到时的客观说法，失败提示按「发生了什么，原因，下一步」写 | 没法、改不了、不能（报错里）、没改成、没撤成、采纳不了 |
| 清单 | 复制给 AI、复制未保存的改动得到的那段文字 | Markdown（界面提示里） |
| 错误代码 | 保存服务返回的状态码，只作为括号里给 AI 排查的信息 | HTTP 500 这类写法 |
| 专门的显示方式 / 通用方式 | 某类内容还没有专门做好的版块，先按原样或通用方式列出 | 枝干、主干、专门模块、其他格子 |
| 我的版本、写给 AI、写给 AI 的话、采纳、不采纳、通读、复制提词稿、内容已确认、冲突、改动记录、整体意见、录完的定稿、叙事、对照 | 已经定下的词，原样保留 | 无，原样保留 |

表里标「显示词」的几项（结论、决定、依据、来源，以及保存状态条里的打开方式）只在显示时换说法：文件里存的值、代码里的比较和复制给 AI 的清单一律用原值，映射表在 `template/app.js` 的 `VERDICT_TEXT`、`DECISION_TEXT`、`BASIS_TEXT`、`SOURCE_TEXT` 和 `kit/kit.js` 的 `MODE_TEXT`。
