# 配置说明

工作台只有一个设置文件：

```
~/Library/Application Support/jincheng-workbench/config.json
```

第一次运行 `pnpm start` 时按默认值自动写出来。改设置就是改这个文件，改完要停掉工作台（Control+C）再运行一次 `pnpm start` 才生效。

改的时候注意：

- 它是 JSON：文字要用英文双引号 `"` 括起来，最后一项后面不能有逗号。最好用代码编辑器改，或者交给 AI 改；「文本编辑」可能把引号自动换成中文引号，文件就坏了。
- 写坏了不会悄悄用默认值顶上：`pnpm start` 会停下来，告诉你是哪个文件、大概第几行。改好，或者把这个文件删掉（下次启动按默认值重新生成），再启动。
- 某一项的值不对（比如端口写成了本机常见服务在用的端口），那一项按默认值处理，启动时在终端和页面最上面都会说清楚是哪一项。
- 不认识的项（比如拼错了名字）会提醒，但不会让工作台停下。

  "workFolder": "~/Documents/jincheng-workbench",
  "paths": {
    "topics": "选题库",
    "overview": "选题库/00_选题总览.md",
    "drafts": "内容草稿",
    "writingMethod": "写稿方法",

## 每一项

### 说明

给打开这个文件的人看的一句话，工作台不读它。

### workFolder：工作文件夹

- 是什么：放你全部内容的文件夹。下面 `paths` 里写的相对路径都接在它后面。写稿、调研的结果都写进这里；两个 Skill 自己从设置里查到它，在 Codex 或 Claude Code 里不用先打开它。
- 默认：`~/Documents/jincheng-workbench`（`~` 是你的家目录）。
- 怎么改：写成别的文件夹，比如 `"~/写作"`。这个文件夹不存在时，下次启动会建好，并放进示例和 AGENTS.md、CLAUDE.md；已经存在的文件夹，工作台不往里写 AGENTS.md 和 CLAUDE.md，只补缺的子文件夹。
- 搬过工作文件夹：把这一项改成新位置，不然下次启动会在旧位置重新建一个空的。

### paths：每类东西放在哪

每一项可以写三种：相对路径（接在 `workFolder` 后面）、`~/` 开头的路径、`/` 开头的完整路径。

| 项 | 是什么 | 默认 |
| --- | --- | --- |
| `topics` | 选题库：里面按内容类型各有一个文件夹，每类再分「待做」「已做」，放选题卡 | `选题库` |
| `overview` | 选题总览：全部选题一张表 | `选题库/00_选题总览.md` |
| `drafts` | 内容草稿：每条内容一个「编号_选题名」文件夹，创作页也放在里面 | `内容草稿` |
| `writingMethod` | 写稿方法：你自己的写稿方法和判断，AI 写稿和给改稿建议前都会先读 | `写稿方法` |
| `benchmarkAccounts` | 对标账号：每个账号一个「平台-账号名」文件夹，里面一份 `档案.json` 和几张图片 | `市场调研/对标账号` |
| `researchReports` | 调研报告：每份报告一个「日期_主题」文件夹，里面是网页和 `meta.json` | `市场调研/调研报告` |
| `commentImports` | 评论导入：社媒助手导出的评论表（Excel、CSV、TSV、JSON），AI 分析评论时读这里 | `市场调研/评论导入` |
| `prompts` | 提示词文件夹：一条提示词一个 md 文件，子文件夹就是分类 | `提示词` |
| `promptUsage` | 提示词的复制和收藏记录（工作台自己写，一行一条） | `提示词/_使用记录.jsonl` |
| `trash` | 回收站：在页面上删除的提示词挪到这里，不会永久删除 | `回收站` |

改了某一项以后，原来那个位置的文件不会自动搬过去，要自己挪。

创作页要放在工作文件夹里面：保存服务只在工作文件夹里找页面。所以 `drafts` 写成工作文件夹以外的地方时，那里的创作页打得开、但改动存不回文件。

市场调研的三个文件夹默认都在工作文件夹的「市场调研」里，那一层有一份 `README.md`，写着三个文件夹放什么、文件是什么格式。三个文件夹改到了没有共同上一层的地方时，不写这份说明。调研 Skill 也按这三项找文件夹。

### contentTypes：内容类型

- 是什么：选题分成哪几类。每一类在选题库里有一个同名文件夹，在选题总览里有一节「### 类型名」，「内容」页上方的筛选按钮也按它来。
- 默认：`["教程", "科普", "口播"]`。
- 怎么改：写成你自己的分类，比如 `["长视频", "图文", "直播"]`。要求：1 到 12 个、不重复、每个不超过 20 个字、不能带 `/` `\` `:`、不能以点开头。不符合要求就整项按默认值处理。
- 改完还要做：下次启动会在选题库里补上新类型的文件夹；选题总览里要自己加一节「### 新类型」（照旧的写法，「**待做**」「**已做**」两张表）；工作文件夹里的 AGENTS.md 是第一次启动时按当时的类型写的，记得把里面的类型名改一下。
- 选题总览里有设置里没有的类型，那几条选题不会显示，页面上会提醒是哪一节、几条。

### columns：显示哪几个栏目

- 是什么：左边菜单显示哪几栏。
- 能写的：`"content"`（内容：选题、在做）、`"research"`（市场调研：对标账号、调研报告）、`"prompts"`（提示词）。左边菜单按这个先后排，跟你写的顺序无关。
- 默认：三个都开。
- 怎么改：只要提示词就写 `["prompts"]`。至少开一个。关掉的栏目，它的文件夹不会自动建，接口也不提供它的数据。
- 升级前就有的设置文件里没有 `"research"`：想用市场调研，把它加进 `columns`，重新运行 `pnpm start`。

### ports：端口

- 是什么：工作台在本机开三个服务，`api` 是接口（后台），`ui` 是你在浏览器里打开的界面，`save` 是创作页的保存服务（把你在创作页上改的字存回文件，用 Python 3 运行）。
- 默认：`api` 18878，`ui` 18879，`save` 18977。
- 被占用时：`pnpm start` 会自动往后找空的端口，并在终端里说换成了哪个，打开地址以终端打印的为准。创作页的链接由工作台按这次实际的端口给出，不用自己改。同一台电脑上另一份工作台（用别的设置文件起的，比如换了 `WORKBENCH_CONFIG_DIR`）占着这些端口时也一样往后找；已经在运行的就是这一份（同一个设置文件）时，`pnpm start` 不起第二份，直接打印它的地址。
- 不会用的端口：8878、8879、8888、8890、8977、8978、8787、43127 这几个是本机常见服务在用的，写了也会按默认值处理。端口要在 1024 到 65535 之间，三个不能一样。
- 设置里关掉了「内容」栏（`columns` 里没有 `content`）时，不起保存服务，也不需要 Python。

## 环境变量（一般用不到）

| 变量 | 作用 |
| --- | --- |
| `WORKBENCH_CONFIG_DIR` | 换设置文件所在的文件夹，比如同一台电脑上跑第二份工作台、或者测试时用 |
| `WORKBENCH_LOG_DIR` | 换日志文件夹，默认 `~/Library/Logs/jincheng-workbench` |
| `WORKBENCH_DRY_OPEN` | 设成 `1` 时，「打开」「在访达中打开」只记进日志、不真的打开，自动化测试用 |
| `TIKHUB_API_KEY` | 有值时 TikHub 用这个 key，不用钥匙串里存的（「市场调研」页上会写明用的是环境变量里的） |
| `WORKBENCH_KEYCHAIN_SERVICE` | 换 TikHub 的 key 在钥匙串里的服务名（默认 `tikhub-api`）。只给测试和验收用，免得碰到真的那一项 |
| `TIKHUB_BASE_URL` | 换 TikHub 接口的地址（默认 `https://api.tikhub.io`），测试时指到假的 TikHub |
| `WORKBENCH_AI_LINKS` | 新手指引第 3 步「在 Codex 里打开」「在 Claude Code 里打开」按钮放不放，默认问这台 Mac 有没有程序接这两种链接。写成 `codex,claude`、`claude` 或 `none` 就照写的来，只给测试和验收用 |

TikHub 的 key 不在设置文件里：在「市场调研」页上粘贴、检测通过后，存进这台 Mac 的登录钥匙串（服务名 `tikhub-api`，账户名 `tikhub`）。设置文件里也不记「接没接好」，每次都从钥匙串现查。

## 日志

两个服务的输出都写在 `~/Library/Logs/jincheng-workbench/workbench.log`，每行前面有时间和是哪个服务（「接口」「界面」「编译」「启动」）。出问题时看最后几十行：

```bash
tail -50 ~/Library/Logs/jincheng-workbench/workbench.log
```
