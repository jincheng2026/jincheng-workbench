## 这个仓库是什么（2026-10-02 定）

- 公开的是「代码仓库 + 一份让 AI 照着装的说明」。别人把仓库链接交给 Codex 或 Claude Code，说「照这个帮我装好」，AI 在他电脑上装起来跑。不打包 App、不签名。
- 这个公开仓库是**上游**：原作者自己每天用的工作台以后也要换成从这里拉更新。所以路径、内容类型、显示哪几个栏目都从设置读；原作者自己的私人栏目以后放在不公开的地方叠加，**不进这个仓库**。代码、文档、示例里不出现真实的人名、本机路径、域名、账号。
- 第一版带：「内容」栏的「选题」「在做」两个页签（含每条内容的详情页）和「提示词」栏；2026-10-03 加上「市场调研」栏的「对标账号」「调研报告」两个页签，见下面「市场调研」一节。
- 第一版不带：今天页、任务看板、已发布（要读内容数据档案）、封面、私域客服、运动、个人网站。X 收藏不带：它靠浏览器登录状态抓网页内部接口，违反平台条款，分发出去会连累作者的账号。
- 写稿用的「创作页」2026-10-03 定下要带，连同配套的写稿 Skill 和工作文件夹里的「写稿方法」，见下面「创作页」一节。创作页不是「内容」栏的页签：每条内容一个，从详情页和「在做」的卡片上打开。
- 版本（2026-10-04 记）：0.1.0 在 2026-10-03 晚公开（原作者的同事急着用），同晚推了 0.1.1。1.0 换成一个从头开始的新仓库，只有一条提交，原作者 10-03 定的（原话：「我明天还是要新开仓库的，要不然它会有旧的那个记录，我不想要有那个旧的记录」），10-04 同意的做法：旧仓库改名成 jincheng-workbench-0.1、设成不公开，不删（要删得原作者自己在 GitHub 设置里删）；新仓库用原来的名字，README 和安装那句话里的链接都不变。0.1 时装的那份 `git pull` 接不上，安装说明第 0 步用 `git merge-base` 认出来，旧代码挪到 `~/jincheng-workbench-0.1` 留着、重新下载，工作文件夹和设置不动（真跑结果见「交给 AI 的话」）。以后的版本都在这个新仓库里往下提交，不再从头换。

## 文件放在哪

- 设置：`~/Library/Application Support/<id>/config.json`，第一次运行按默认值写出。只读不改；写坏了直接报错并说第几行，不悄悄用默认值顶上（用户会以为自己的设置生效了）。单项写错按默认值处理并提醒。
- 日志：`~/Library/Logs/<id>/workbench.log`（macOS 惯例）。
- 用户的内容：工作文件夹，默认 `~/Documents/<id>/`。
- 第一次启动自动建好工作文件夹：选题总览（带说明和一条示例 T001）、各类型的「待做」「已做」文件夹、一张示例选题卡、内容草稿（示例选题 T001 的草稿文件夹里放好一份虚构的参考视频逐字稿 `参考素材/参考视频逐字稿.md` 和照「写稿方法/03」写好的 `参考拆解.md`，新用户第一次让 AI 写 T001 就有东西可拆，2026-10-03 加）、写稿方法（说明和七份默认写法，2026-10-03 加）、提示词（格式说明、分类顺序、两条示例），最外层给 AI 看的 AGENTS.md 和 CLAUDE.md（CLAUDE.md 用 `@AGENTS.md` 引用，只维护一份）。
- 创作页的保存服务在工作文件夹里留三个以 `.` 开头的文件夹：`.jc-locks`（文件锁）、`.jc-versions`（每次写入前的旧文件，每页留最近 20 份）、`.jc-changes`（每存一格记一行）。工作台的文件列表和打开文件都不进以点开头的文件夹。
- 只补缺的、从不覆盖：示例只在对应文件夹是这次新建时才写，用户删掉的示例不会再冒出来。工作文件夹原来就有（比如指向用户已有的资料库），不往里写 AGENTS.md。选题总览不见了，启动时补一份空白的；页面上也有「重新建一份空白的选题总览」。
- 提示词的复制和收藏记录放在提示词文件夹里的 `_使用记录.jsonl`（以 `_` 开头，不会被当成提示词），算用户的数据，跟着工作文件夹走。
- 页面上删除提示词：挪进工作文件夹的「回收站」，文件名前面加日期和分类，不永久删除。

## 选题和草稿的规矩

沿用原工作台的一套：T 编号（T001 起，定了不改不复用）、选题总览一张表、每条选题一张卡、每条内容一个草稿文件夹。读法在 `lib/works.mjs`：

- 选题总览「## 选题总表」下面按「### 类型」「**待做**」「**已做**」分组；类型标题里的空格不算（「AI 教程」和「AI教程」是一类）。写在设置里没有的类型下面的行不显示，但页面会提醒是哪一节、几条，不悄悄丢掉。
- 内容类型改成设置项，默认「教程、科普、口播」。
- 选题卡认两处：`<类型>/<待做|已做>/T001_*.md`，也认直接放在 `<类型>/` 下的。
- 草稿文件夹按编号前缀认（`T001_` 开头）。文件按名字认：工作稿/初稿/逐字稿是正在写的稿子，定稿/最终稿/录制版是定稿，提词器是提词器版，改稿日志单独认；「版本」子文件夹只数个数；脚本和数据文件不列。
- 做到哪一步全部从文件现算：总览放在「已做」、标了 ✅、状态是已发布 → 做完了；状态是草稿、草稿 14 天内有改动、草稿文件夹里已经有稿子 → 在做（参考材料不算：「参考素材」文件夹里的东西和「参考拆解」改了不算草稿有改动，也不当「接着写」的稿子，2026-10-03 加，示例选题带着参考材料也还在「选题」里）；其余 → 待做。只报能从文件确认的对不上的地方（最多三条）。
- 加选题（2026-10-04 加）：`scripts/add-topic.mjs`（逻辑在 `lib/topics.mjs`），写稿 Skill「加选题」和「选题」页的「复制给 AI：加选题」都靠它。编号取选题总览的表格行、选题库的文件名、内容草稿的文件夹名里出现过的最大编号加一（总览开头说明里的 T001 不算；作废、删掉的编号不再用）；只往对应类型的「待做」表末尾加一行，按那张表自己的表头填，别的行一个字不动；这一类还没有「### 类型」或「**待做**」表时，照新建总览的样子补上；选题卡照工作文件夹 AGENTS.md 的格式，用户的原话放进备注；加完用 `readWorks` 再读一遍，工作台认得出来才说加好了。同名的不重复加（AI 重试时不会加出两条）。设置和工作文件夹还没有时，跟 `pnpm start` 一样先建好。不让 AI 手改表格：编错号、加错格、表格断开，工作台就读不到。
- 接口里文件用「位置:相对路径」表示（`topics:…`、`drafts:…`），因为选题库和内容草稿可以在设置里放到不同的地方；打开文件前先核对它确实属于这条内容，再消解软链接确认还在设置的文件夹里。
- 从原工作台拿掉的：全库网页归集和页面服务、对照页编辑服务、已发布视频档案、参考视频、选题卡里提到的库外路径。这些依赖原作者自己的目录结构和服务，第一版不带。

## 打开文件

- 「接着写」「打开选题卡」这类动作交给系统默认程序（和在访达里双击一样，`/usr/bin/open`），不假设装了某个编辑器。文字文件没有默认程序时退一步用「文本编辑」打开。文件夹在访达里打开。
- 只用 `execFile`，不经过 shell；路径必须在设置里的文件夹里面。
- 环境变量 `WORKBENCH_DRY_OPEN=1` 时只记日志不真的打开，自动化测试用；测试里用 `tests/helpers.mjs` 的假打开器。

## 启动、端口和界面怎么连到接口

- `pnpm start`（`scripts/start.mjs`）一条命令：读设置、建工作文件夹、界面没编译或代码更新过就先编译、挑端口、拉起接口和界面、等两边都能应答再打印打开地址。两个服务的输出写进日志，终端里只打印要紧的话。Control+C 两边一起停。
- 端口默认接口 18878、界面 18879、创作页保存服务 18977，被占就往后找空的。8878、8879、8888、8890、8977、8978、8787、43127 是本机常见服务在用的端口（8977、8978 是原作者自己的创作页正式版和预览在用，2026-10-03 加上 8978），写进 `lib/ports.mjs` 的 `BLOCKED_PORTS`，无论设置怎么写都不用。判断端口空不空：先看有没有程序应答（覆盖只监听 0.0.0.0 或 ::1 的程序），再试着监听。
- 已经在运行时再 `pnpm start`：从界面端口往后问 `/api/health`，是自己就直接打印界面的地址退出，不起第二份。「是自己」看 `/api/health` 回答的 `instance`：设置文件路径算出来的 16 位记号（`lib/config.mjs` 的 `instanceId`，不带路径本身）。2026-10-03 发布前验收时改的：原来只看名字对不对，同一台电脑上用别的家目录或 `WORKBENCH_CONFIG_DIR` 起的另一份占着默认端口时，新的一份会以为自己已经在运行，把用户带到别人的工作文件夹去。`/api/health` 同时回答界面这次的端口（`ui`）：端口被挪过时先问到的可能是接口的端口，打印的要是界面的。
- 界面里的 `/api/*` 由 `ui/app/api/[...path]/route.ts` 在运行时转给接口。没用 `next.config` 的 rewrites，因为 rewrites 在编译时就写死了地址，接口换端口就连不上。转发前检查 Host 必须是 127.0.0.1 或 localhost，挡住把别的域名解析到本机的网页（DNS 重绑定）。
- 接口自己也检查：Host 必须是本机接口地址；带 Origin 的请求必须来自本机的界面或接口；写操作必须是 JSON。
- 根布局在服务端向接口要一次基本信息（开了哪些栏目、工作文件夹在哪），所以页面都是运行时渲染（`force-dynamic`），改设置不用重新编译界面。
- 编译成功后在 `ui/.next/workbench-build.json` 记下界面代码最新的修改时间，`pnpm start` 发现代码更新过（比如 `git pull` 以后）就先重新编译。编译时自动生成的 `next-env.d.ts` 不算。

### 要不要 Python

- 结论：保留 Python，不改写成 Node。保存服务 `brain_save.py` 只用 Python 标准库（`http.server`、`fcntl`、`json`、`hashlib` 等，查端口占用者时调系统自带的 `/usr/sbin/lsof`），`build_page.py`、`brain_page.py`、`creation_doc.py`、`where.py` 也只用标准库，不用 `pip` 装任何东西。macOS 的「命令行开发者工具」带 Python 3（装 Git 时一起装的），系统自带的 3.9 和 Homebrew 的 3.13 都跑通了全部测试。最低要 3.8（`pnpm start` 和 `lib/creation.mjs` 的 `findPython` 会查）。
- 安装说明加了「确认有 Python 3」一步（第 3 步），README 的「需要什么」也写上了。
- 改写成 Node 不划算：这几个脚本有一万多行（含测试），逐格保存、文件锁、同号多份、来源隔离都有大量测试兜着，改写等于重做一遍，也没法再和 2.0 同步。

### 怎么启动

- `pnpm start` 在「内容」栏开着时：先找 python3（环境变量 `WORKBENCH_PYTHON` 可以换，默认 PATH 里的 `python3`），找不到就停下并说怎么装；再挑第三个端口（设置里的 `ports.save`，默认 18977，被占往后找，避开接口和界面的端口），拉起 `python3 creation-page/server/brain_save.py --root <设置里的工作文件夹> --port <端口> --skip-dir <回收站>`（回收站在工作文件夹外面时不加），等它的 `/healthz` 回答、而且根目录就是这次的工作文件夹，才算启动好。输出写进同一个日志，标签「保存」。Control+C 和接口、界面一起停；它意外停了，另外两个也一起停（和接口、界面一样）。
- 接口从环境变量 `WORKBENCH_SAVE_PORT` 知道保存服务这次的端口，给创作页的链接用它，不用设置里写的（端口可能被挪过）。页面数据里写的保存服务地址（直接双击打开文件时用）按设置里的端口写。

### 页面放在哪、工作台怎么认

- 沿用原来的做法：每条内容一个创作页，放在它的草稿文件夹里，`内容草稿/T001_选题名/T001_创作页.html`。保存服务的根目录是工作文件夹，所以 `paths.drafts` 写到工作文件夹外面时，创作页打得开但存不回（配置说明里写了）。

## 市场调研（2026-10-03 加）

### 要做到什么

### 数据来源：TikHub

- 卡片一步步带：注册（`https://user.tikhub.io/register`，要验证邮箱）→ 拿 key（`https://user.tikhub.io/dashboard/api`，创建时要把权限范围全部勾上，不勾会报 403）→ 粘贴后只有一个「检测并保存」按钮。2026-10-03 改成「检测通过才存」：先调查账户信息的 `get_user_info`（官方单价查询接口查到是 0 美元一次），通过了才写进钥匙串；没通过时钥匙串里原来的 key 不动。原来设想的「先存、再测试连接」会把错的 key 存进去，用的时候才失败。
- 出错说人话，按钮就在旁边：401 key 不对或已停用（回 TikHub 重新复制）、403 邮箱没验证或没勾权限（去勾权限）、402 余额不够（去充值）、连不上（检查网络或代理后重试）。余额是 0 也算接好，只是提醒充值。卡片上写明「新号送的 0.05 美元只够试抖音，小红书的接口不能用送的额度，做小红书要先充 5 美元」。
- 只用 `api.tikhub.io`：官方现行公告要求用它，别用 `api.tikhub.dev`。
- TikHub 报错时会把请求头原样放进回答里（里面就有 key），所以它的回答只取状态码和余额这几个数，原文一个字都不往页面、日志里传。
- 费用：页面上写「大概花多少钱」，按「常见调研要调几次哪个接口 × 单价」算（`lib/data-sources.mjs`）。单价优先用 TikHub 公开的单价查询接口（不用 key）现查，查不到用 10 月 3 日查到的兜底值；只在用户点「检测并保存」和接好 TikHub 以后才去查（12 小时内不重复查），没接的时候打开页面不连外网，README 里「工作台本身不连任何服务器」的说法照样成立。人民币按 1 美元约 7 元粗算，页面上写明。
- 接好以后，进页面时用免费的 `get_user_info` 查一次余额（10 分钟内查过就不再查），卡片写「已接好，余额 $x」；检测结果只记在接口进程的内存里，不写文件。

### 钥匙串

- key 只存 macOS 登录钥匙串，服务名 `tikhub-api`、账户名 `tikhub`：和原作者本机已有的那一项一样，他以后换成这个工作台不用再填。环境变量 `TIKHUB_API_KEY` 有值时优先用它。
- 用系统自带的 `/usr/bin/security`：写入用交互模式（`security -i`），整条命令从标准输入给，key 不出现在进程参数里；读的时候只取「有没有、后四位」给页面；左边菜单的「还差几步」只查这一项在不在，不读出 key。
- 设置文件里不记 key，也不记「接没接好」：设置文件是「只读不改」的，接没接好每次从钥匙串现查，余额只在内存里。
- HOME 被换掉时（比如在临时家目录里验收）`security` 找不到默认钥匙串：写会卡住、读会找不到。这时按系统账户里记的家目录（`os.userInfo()`，不看 HOME）写明登录钥匙串的路径；平时不写，照系统默认（`lib/tikhub.mjs` 的 `explicitKeychain`）。
- 测试和验收一律用测试专用的服务名（环境变量 `WORKBENCH_KEYCHAIN_SERVICE`，`tests/helpers.mjs` 每次运行换一个），测完删掉，绝不读写、删除真的 `tikhub-api`。接口测试用内存里的假钥匙串。

### 数据来源：社媒助手

- 深圳隙生科技有限公司出品的浏览器插件，不开源。2026 年 7 月旧的商店地址被停用，换了新地址重新上架：卡片给新的 Chrome 商店地址，打不开（比如在中国大陆）就给官网下载页 `https://socialext.com/download`，不写旧的插件编号。
- 卡片带：建一个只给小号用的 Chrome 个人资料 → 装插件 → 用小号登录小红书、抖音（附官方安全建议：小红书单号每天不超过 200 篇、间隔 30 到 60 秒，连续多天触发风控可能被限流甚至封号）→ 侧边栏「批量采集」选评论、粘链接、导出 Excel（也可能是 CSV、TSV）→ 把表拖进页面或「选择文件」。

- 社媒助手的条款不许传播导出的数据：仓库里不放任何导出样例，测试用的表都是虚构的（`tests/helpers.mjs` 现拼）。

### 和界面那一路约定的格式

- 工作文件夹里的「市场调研/」，下面三个文件夹：「对标账号/<平台>-<账号名>/」「调研报告/<日期_主题>/」「评论导入/」。三个文件夹的位置读工作台设置的 `paths.benchmarkAccounts`、`researchReports`、`commentImports`（和界面那一路一致，合并时对齐，原来读的 `paths.research` 已不用），没写就是工作文件夹下「市场调研」里的这三个；TikHub 的用量和缓存放在「调研报告」上一层的 `.tikhub/`。

- 约定以外多放了一个 `作品.json`（这次拉到的作品和数据），账号研究直接用它，不重复花钱。没放进 `档案.json`，免得改约定。

### TikHub 的密钥和地址

- 读的顺序：先环境变量 `TIKHUB_API_KEY`，没有再读 macOS 钥匙串（`security find-generic-password -s tikhub-api -a tikhub -w`）。钥匙串条目一开始约定用工作台的英文名当 service，后来改成 `tikhub-api`/`tikhub`，和原作者本机已有的条目一致，他装的时候不用再填。都没读到时只说一句「去工作台『市场调研』页顶部的『数据来源』里配好」，同时给不用 TikHub 的那条路，不报一堆错。
- 密钥只在脚本进程里用：不打印、不写进任何文件（用量记录、缓存、原始返回、报告里都没有），对 AI 只说「已读到（从哪读到）」。查单价的免费接口不带密钥。打印客户端对象也不带密钥。
- 地址只用 `https://api.tikhub.io`（TikHub 现行公告要求，不用 api.tikhub.dev）。环境变量 `TIKHUB_BASE_URL` 只认本机地址，给测试接假服务用；写别的地址一律不理，免得密钥被发到别处。
- 测试一律用 `WORKBENCH_KEYCHAIN_SERVICE` 换成测试专用的 service 名，并且不真的调用 `security`；开发时只用一个测试专用的条目真跑过一次读钥匙串（写入、读到、删掉），没有读、写、删过真实的 `tikhub-api` 条目。

### 钱：单价从哪来、上限怎么定

- 单价：每次花钱前用 TikHub 公开的单价查询接口 `/api/v1/tikhub/user/get_endpoint_info` 现查（不用密钥、不扣费），查不到用兜底单价。兜底单价是北京时间 2026-10-03 用同一个接口查的：抖音（App V3 的作品详情、作品列表、博主资料、评论、楼中楼，Web 的认博主、认作品）每次 0.001 美元；小红书 App V2（博主、笔记列表、笔记详情、评论、楼中楼）每次 0.01 美元；查账户的 `get_user_info` 免费。抖音作品列表和全部小红书接口不能用新账号送的试用额度（接口返回的 allow_free_credit 是 false），花钱前用免费的 `get_user_info` 看余额，只有试用额度时先拦下、一分钱不花。原作者自己的数据追踪项目里有一处把抖音每次记成 0.01 美元（高了 10 倍），这里没照抄那个数。
- 估算：抖音评论和作品列表每页 20 条（接口文档要求保持默认）；连楼中楼一起时按每次请求约 3.6 条估（原作者 8 月一次真实采集 128 次请求拿到 459 条折算的）；小红书评论每页条数官方没写，按 10 条估，笔记列表按至少 6 条估。估的是上限（官方原价，不算每天 1000 次以上的阶梯折扣），跑的时候绝不超过计划的请求次数。
- 上限：单次最多自动花 0.02 美元（够抖音 200 条一级评论的 11 次请求，再加一次拉博主作品）、当天累计最多自动花 0.20 美元、评论默认最多 200 条；小红书每次都先问。超过就退出码 3、第一行「需要用户同意：」，把次数和金额写清楚；用户在对话里明确同意后带 `--agreed-budget <金额>` 再跑。原作者自己的研究 Skill 是单任务 120 次或 1 美元自动授权、按计划哈希核对，开源版简化成「计划 + 用户同意的金额」，规矩写在 SKILL.md 最前面。
- 出错：401、402、403、404、400、429、5xx、连不上、超时各有一句人话。报错的请求 TikHub 不扣钱（用量里记 0）；429 和 5xx 自动等一下重试两次；连不上（请求还没发出去）重试一次；发出去以后超时或断开，说「可能扣了也可能没扣」并停下，不自动重试。小红书参数错了照样扣费（TikHub 文档写的），这种情况也说清楚。

### 评论洞察

- 社媒助手导出以 Excel 为主，也可能是 CSV、TSV；JSON（包括 TikHub 原始返回）也能读。Excel 用 Python 自带的 zipfile 和 XML 解析读，不装包；单元格先保留原文（长编号不会变成科学计数法），评论时间是 Excel 日期数字时按列换算（认 1904 日期系统）。CSV 先按 UTF-8 读，不行按 GB18030。
- 认列按常见叫法：社媒助手 2026 年 6 月帮助文档里抖音评论的字段（评论ID、视频ID、视频链接、用户名称、评论内容、评论时间、IP地址、点赞数、子评论数、一级评论ID……）、老版本的「点赞量」「评论图片链接」、英文字段名都认；表头里带着三个字以上的常见叫法也认（取最长的）。认得但不用的列（用户编号、主页、抖音号、引用的评论……）和认不出的列都写进报告的「数据说明」。认不出评论内容那一列就停下，把表头给用户看。
- 一张表里几条视频（或笔记）的评论按编号或链接分组；用户说了是哪条就只取那条，没说又有好几条就停下问。
- 清洗：按评论编号去重（没有编号时按视频、原文、时间、昵称）；空白、只有图片、只有表情或 @、只有一个字算没法分析，单独计数、不进分母；有「一级评论ID」就分一级和回复，回复记下挂在哪条下面；TikHub 数据里作者本人的回复做标记。评论者的昵称、编号、主页不存进评论数据，也不进报告。
- 分工：AI 读完全部有效评论（`comments show` 分页列出），归类、写结论和选题，写成只含评论短号（c1、c2……）的 `分析.json`；程序核对每个短号存在、不是无效评论、摘录和原文一字不差、结论和选题都有依据，条数、点赞、属地都由程序从原文算。核对不过就不出报告。
- 报告第一屏是「先说结论」（3 到 5 条，每条带依据条数和一句原话）和「可以直接拍的选题」（拍给谁、依据多少），往下才是分类（条数、占比、点赞、原话，全部原话可展开）、评论的都是谁、样本够不够、数据说明。原作者以前对评论报告最不满意的是报告本身，所以不让图表和统计占第一屏。
- 样本够不够的规则（报告里写着）：一类 10 条以上「够看出方向」、4 到 9 条「有一些，还要再看」、3 条以下「很少，只是线索」；有效评论不到 30 条整份报告顶上写「只当方向参考」，不到 100 条写「条数少的分类只当线索」。这几个数是这次定的经验值，没有出处，用户觉得不合适可以改 `comments.py` 的 `sample_label`。
- 归类方法用用户研究里通用的做法（逐条贴「在说什么」的短标签，再把意思相近的合成一类），分类只分需求、痛点、疑问、反馈、求资料、其他六种，写在 `references/评论洞察怎么做.md`。

### 拆视频和账号研究

- TikHub 没有抖音、小红书、视频号的字幕或逐字稿接口：拆视频只拿标题、文案和数据，要拆讲法就请用户贴逐字稿，SKILL.md 里直接这么写，不假装能拿到。抖音作品详情的字段对着 TikHub 官方免费演示接口（`/api/v1/demo/douyin/app/fetch_one_video`）的真实返回核对过。
- 拆法按用户工作文件夹「写稿方法」里的 `03_拆参考怎么拆.md`（默认五件事），属于某条选题时追加进它草稿文件夹的「参考拆解.md」：一条参考只拆一次，同一个链接已经拆过就拒绝并说在第几行。也可以另出一份「视频拆解」报告；给了逐字稿时核对每句引用都能在逐字稿里找到（标点、空格不算）。
- 账号研究不做模型，规则写进报告：互动数 = 点赞 + 评论 + 收藏 + 分享；发布满 3 天的作品取中位数当平时水平；达到 2 倍算明显更火；发布满 3 天、数据齐的不到 8 条只排序不判断；点赞、评论、收藏、分享里涨得最多的那一项，是这一项平时的 2 倍以上、又比整条的倍数高，才单独标出来（四项都涨时全列出来太吵，只标最突出的一项）。抖音 App 接口的播放量总是 0，不用。AI 可以在 `分析.json` 里补「这几条有什么共同点」，每条观察要写是哪几条作品。

### 没带过来的东西和原因

- **课程方法**：原作者评论可视化 Skill 里，分析需求、人群、情绪、买点、信任、流量、表达时会路由到他上过的一门付费课程整理出来的一组 Skill。这些一个字没抄，也没有改写后放进来，报告和说明里不出现那门课和那组 Skill 的名字；评论洞察改用上面的通用归类做法。同一个 Skill 里还写着「需要时参考另一位老师的选题结构、需求阶段与购买顾虑方法」，也是别人的方法，没带。
- **拿不准出处、没带的**：原作者社媒研究 Skill 里拆账号定位的「三层框架」（个人定位、账号定位、内容定位）和拆视频 Skill 里「为什么停下、为什么继续、为什么相信……」那一套拆法，参考文件里没写出处，拿不准是不是来自课程或付费内容，都没带；拆视频按用户自己的「写稿方法」来。
- **原作者个人的东西**：他自己的门槛（抖音 AI 教程 100 到 2 万粉、1000 赞算低粉爆款）、知识库和项目路径、分析他本人账号时的「个人化建议」和跨视频老粉名单、对标对象和真实评论、转写用的云服务和本机模型、报告里的图表库、计划哈希和发布前机检脚本、视频号下载解密。

  - 按钮带上工作文件夹和复制给 AI 的那句话（按网址编码），Codex 在前。只在这台 Mac 上有程序接这种链接时才放（`lib/ai-links.mjs`：用系统自带的 osascript 问「启动服务」谁来打开 `codex://threads/new` 和 `claude-cli://open`，只问不开，约 0.05 秒，一分钟最多问一次；问不了时 Claude Code 看官方文档写的 `~/Applications/Claude Code URL Handler.app` 在不在），点了没反应的按钮不放。接口 `/api/app` 多了 `aiLinks`。测试和验收用环境变量 `WORKBENCH_AI_LINKS` 指定，不问系统。

## 交给 AI 的话（2026-10-03 定提示词标准）

原作者当天定的标准，全文在 [AGENTS.md](../AGENTS.md)「交给 AI 的话怎么写」。他的原话：「提示词的要求是，用户复制粘贴发给他的AI，就能够直接完成我们要他达成的目的……那只需要哎复制粘贴好，就会自适应，AI就会自适应。」「到这个必须人去做的时候，AI就主动去提醒人……其实我们的核心目标就是提高用户体验……有些地方不能自动化的，我们就不自动化。因为如果搞错的话，反而会影响用户体验。」起因是新手指引第 3 步要用户先「新开对话、打开某个文件夹」再粘贴，他试用时卡在这里。

照标准改了这些：

- 页面上所有「复制给 AI 的话」集中到 `ui/lib/ask-ai.ts`（写稿一句、三种调研、加对标账号、导入评论表后生成报告），`tests/ask-ai.test.mjs` 查得出来的几条在 `pnpm test` 里拦：带 Skill 名字和仓库地址（`brand.json` 的 `repository`，编译时带进界面）、不带这台电脑的路径、要贴的只在最后一处（「…贴在这句后面：」）、要人做的事到了再提醒。原来的调研话术把工作文件夹、对标账号的完整路径和 meta.json 怎么写都塞在话里，还要用户在第一行中间填链接；现在位置由调研 Skill 自己从设置里查，报告格式脚本本来就会写对。
- 新手指引第 3 步：气泡只剩「粘贴给 Codex 或 Claude Code，发出去」「哪个对话都行，写完自动进下一步。」，下面是一键打开的按钮（开在工作文件夹、那句话已经填好，Codex 在前）。当晚加的路径、复制路径、在访达中打开、「怎么在 AI 里打开这个文件夹」整块拿掉了：那句话在哪个对话里发都能做完，摆这些反而是让用户先做准备。
- 两个 Skill：找不到仓库时按顺序自己找（软链、正在运行的进程、聚焦搜索），都找不到就照用户话里的仓库地址装，不问用户；写不了工作文件夹时先用 AI 工具自己的办法申请权限，申请不了才请用户换个对话；保存服务没开、工作文件夹还没建时，AI 直接在后台启动工作台，不再问「要我替你运行吗」。写稿 Skill 收到「做成创作页」的话就直接生成，不再问一次；调研 Skill 拆视频没说是哪条选题时只出报告，不先问。
- 后台启动和停止：`pnpm start --background` 把工作台另起成脱离终端的进程，等它打印「已经启动」才结束，关掉终端、关掉 AI 的对话都不停（AI 的命令跑完就结束，原来只能请用户自己开一个终端一直开着）；`pnpm stop` 停掉同一个设置文件起的那一份（问 `/api/health` 认出是不是自己，用 `lsof` 查出听端口的进程，停它的上一级 `scripts/start.mjs`），旧版本起的也能停，更新时先停旧的。
- 安装说明加了第 0 步「看看装到哪一步了」：同一句话管第一次安装、更新和重新打开。装过的先 `git pull --ff-only`，没有新提交就直接启动打开，有新提交先 `pnpm stop` 再从装依赖往下做；默认位置被别的东西占了就换个文件夹名装，不问用户；装 Skill 时 AI 自己是哪个就装哪个、另一个也在就一起装；代理从 `scutil --proxy` 查，查不到才请用户打开代理软件。最后只告诉用户结果和下一步，不再教他去打开哪个文件夹。
- 创作页的「复制给 AI」：清单开头加了一句目的（用写稿 Skill 接着改这一页：读回页面、逐条回复写给 AI 的话、照决定接着改、做完说改了哪些），粘贴给哪个 AI 都知道要做什么。这是从原作者 2.0 拷来以后的又一处改动，以后同步时留着。
- README 的安装那句改成写目的的整句（装好、在浏览器里打开、装过就更新、缺什么直接装、要输密码时提醒），「平时怎么用」改成把同一句话再发一次，或者 `pnpm start --background`。
- 加选题（2026-10-04，0.1.1 照标准改时漏掉的一处）：「选题」页原来那句是「请打开「<本机路径>」这个文件夹……帮我加一条选题：（在这里写你的选题）……」，带本机路径、要用户在中间填空；页面上还写着「在选题总览对应类型的「待做」表里加一行，再放一张同编号的选题卡」，让用户自己改表格。现在是 `askAddTopic`：用写稿 Skill 把我想做的选题加进工作台，让我在「选题」里看到，告诉我编号，选题（一条或几条）贴在最后；编号和表格交给上面「选题和草稿的规矩」里的 `add-topic.mjs`。「选题」页的「下一步」、页头、空白处都放「复制给 AI：加选题」，同一屏只放一个；新手指引的开场卡摊开时，「下一步：加你自己的选题」先不出（两个下一步抢注意力），走完引导（最后一句正是「下一步把你自己的选题交给 AI」）或点「我自己看」再出。「在做」空白时先说把详情页那句话复制给 AI，自己写稿的办法放后面。

## 封面 Skill（2026-10-04 加）

### 是什么、从哪搬来

- 在 `skills/jincheng-workbench-cover/`：`SKILL.md` 给 AI 看；脚本入口 `scripts/cover.py`，实现在 `scripts/cover_kit/`，只用 Python 3.9 以上自带的模块；报告网页的模板 `assets/report.html`；五份参考说明在 `references/`；测试在 `tests/`（`pnpm test` 通过 `tests/cover-skill.test.mjs` 一起跑）。
- 搬自原作者给学员做的「内容工作台」App 里的两个 Skill：拆封面 VI（cover-vi）和做封面（cover-maker），连同那个 App 验收清单里封面的几条（第 1 到 13、28、38 条）。原作者 2026-10-04 定（回「都同意」）：开源版加封面，做成 1.1，两个一起搬；工作台上的按钮都是「复制给 AI」，工作台自己不在后台调 AI；Codex 用它自带的生图（image_gen），Claude Code 没有自带生图，先只给生图提示词；学员版里别人的图、原作者的照片和示例封面一样都不进仓库；课堂默认整个去掉。
- 一个 Skill 管三件事：拆一个对标账号的封面 VI、给一条选题出一批、按工作台上的备注改一张。

### 和工作台约定的文件（两边一起定的，改要两边一起改）

- 工作台设置的 `paths` 多一项 `coverAssets`，默认「封面素材」（相对工作文件夹）。
- `封面素材/封面设置.json`：`photo`（相对「封面素材」的路径，没设是 null）、`benchmark`（对标账号文件夹名，没设是 null）、`batchSize`（一批默认几张，默认 5；原作者 10-04 定）；文件不存在等于都没设。工作台和 Skill 都写它：整份读出来、改一项、先写临时文件再换过去，不认识的键原样留着。Skill 只用 `settings` 命令写。`封面素材/我的照片/` 放照片，`封面素材/收藏/` 放工作台收藏的封面（`T002_封面-03.png`）。风格名不存在设置里，存在那个对标账号 `VI拆解.md` 的第二行「风格名：…」。
- 对标账号文件夹里多三样：`封面/`（拆 VI 用的封面，改名成 K01、K02……，改名前后的对照在 `封面/原文件名.md`）、`VI研究/`（records.json、inventory.json、study.json，格式照 `references/evidence.md`）、`VI拆解.md`（出封面时读的拆解）。
- 对照网页出在「调研报告/<日期>_<账号名>封面VI/」：`index.html`、图片副本、`VI规范.md`、清单和研究数据、`meta.json`。`meta.json` 的字段照 `lib/research.mjs` 读调研报告的那几个，`type` 新加一种「封面VI」，`source` 写对标账号文件夹名，`pages` 写 `["index.html"]`。
- 内容草稿：`<编号>_<名字>/封面候选/` 里放候选 `封面-NN.png`（也收 jpg、webp）、每张的提示词 `生图描述-NN.md`、`生成计划.md`（第 N 批是 `生成计划-第N批.md`）、`生成记录.md`、工作台存的批注图 `批注/`；选定的那张是草稿文件夹里的 `封面-选定.<扩展名>`，由工作台复制。编号两位起（满 99 用三位），一直往后编，不复用、不覆盖：删掉的（挪进回收站）、收藏过的、生成记录里提过的编号都算用过。
- `生成记录.md` 的样子写在 `scripts/cover_kit/record.py` 开头：一批一个「## 第 N 批」小节，第一行是这批的对标、照片、日期、软件、生图方式，下面是「编号 | 本张变化 | 自检 | 文件名」的表和一行统计；「## 记录」一行一件事。批次小节只由 AI 用 `record` 命令写；工作台只往「## 记录」后面加。`tests/` 里有一条测试拿约定里的样子一字不差地比。

### 搬过来时改了什么

- **课堂默认整个去掉**：学员版没换照片和对标时，默认用原作者的照片和一位博主的 VI，还会问「要不要删课堂默认」、给一个教程链接。现在没有照片、没有对标时，AI 做到那一步停下，提醒用户放照片（工作台详情页「放照片」，或者把照片拖进对话）、先拆一个对标（提示词标准第 5 条），不替用户选。
- **不问风格名、不问要不要设默认**：学员版拆完要用户回风格名、回「设为默认」才往下走。现在 AI 自己起四到八个字的风格名（写进 `VI拆解.md` 第二行）；用户还没有默认对标就直接设成默认，交付时告诉他在工作台对标账号卡片上能改。
- **只分 Codex 和 Claude Code**（两家并列时 Codex 在前）：学员版另外两家 AI 工具的生图路线和它们的 Skill 目录说法都去掉。Codex 生成一张后，`save` 从 `$CODEX_HOME/generated_images/`（没设就是 `~/.codex/generated_images/`）拿最新的那张存成下一个编号；最新的一张超过 15 分钟、或者和已有的候选一模一样，就停下（多半这次没生成出来）。Claude Code 每张写完整提示词存成 `生图描述-NN.md`，登记时自检写「只出了提示词」，交付时说清复制到能生图的工具里、出好的图存成同名的 `封面-NN.png` 放进封面候选。
- **配置文件和小脚本**：学员版的 `封面配置.md` 换成工作台也读写的 `封面设置.json`；改配置的六个小脚本（检查配置、设照片、设对标、确认默认、删默认和它们共用的一个）换成 `settings show`、`set-photo`、`set-default`、`batch`。
- **脚本改成一个入口、英文名的子命令**：学员版是三个中文名脚本加六个配置小脚本，现在都在 `cover.py` 里：`where`、`vi prepare|inventory|check|build|export`、`settings`、`record batch|add|note|summary`、`save`。输出和报错都是中文大白话、路径打印完整的；有问题退出码 2，第一行就说怎么办；程序自己的问题退出码 1，带出错位置。
- **Pillow 改成可选**：学员版的 vi.py 离不开 Pillow。现在宽高从文件头读（PNG；JPEG，连拍摄方向，竖拍的宽高对调；WebP 的三种写法；GIF），重复按文件内容的 sha256 认；装了 Pillow 时多做两件事：逐张真的解码一遍确认图没坏，按像素认重复（同一张图换了元数据也认得出）。没装时 `vi inventory` 在限制里写一句。缩略图学员版本来就没有，报告网页直接用原图副本。环境变量 `COVER_NO_PILLOW=1` 当作没装，给测试用。
- **文件位置照约定**：研究数据在对标账号文件夹的 `VI研究/`，对照网页出在「调研报告」，工作台「市场调研」里能看到；同一天再出一次另起一个 `-2` 文件夹，不覆盖旧的。清单里图片的路径写成相对 `VI研究/` 的，不写本机完整路径，报告里也没有。`VI拆解.md` 里的原图链接指向 `封面/K01.jpg`。
- **补封面**：学员版要用户自己把封面下载进文件夹。现在 `vi prepare` 在 `作品.json` 有封面链接、`封面/` 又不够 30 张时，按发布时间从新到旧下载，下过的作品不重下；也能 `--from` 从别的文件夹复制进来（原文件夹不动；`--from` 写的是对标账号文件夹本身时只拿「代表作封面」，头像和主页截图不是封面）。然后不叫 Kxx 的图按顺序改名（知道发布时间的从新到旧，不知道的按文件名），不删图；heic 这类报告网页显示不了的记下来不纳入，提示用 macOS 自带的 `sips` 转。下载时分开「链接过期」（服务器回了拒绝）和「连不上网」（多半是 AI 工具的沙箱不让命令联网）：后者在第一张就停下，说用能联网的权限再跑，不说链接过期。
- **生成记录不让 AI 手改**：`record` 命令照约定写小节、表头、行、统计和「## 记录」，和 `scripts/add-topic.mjs` 一个道理。写回前文件被工作台改过（比如刚追加了一行「选定」），就重新读、重新改，最多 5 次。`record add` 拦下：编号用过了、文件还没存进封面候选、文件名和编号对不上、自检超过 30 个字。`record batch` 在最新一批一张都还没登记时接着用它，不留空的小节；草稿文件夹还没有就照工作台「建草稿文件夹」的叫法建（选题名先看选题卡标题，再看选题总览）。只出提示词的一批，统计那一行写「只出了提示词 N 份，没有生成图片」（约定里只有出图那一种写法，这一种是这里定的）。
- **挑选和改图交给工作台**：学员版「收到评分之后」整段（用户在页面上打分，复制「封面挑选结果」贴回来，AI 再选定、记原因、改图）去掉了：选定、收藏、删除、批注都在工作台详情页上点；改一张走工作台复制的「按备注改」那句话，新图用下一个编号、登记进当前这一批（本张变化写「改自 封面-NN：……」），「## 记录」记一行「按备注改 封面-NN → 封面-MM」。每次都是全新的一次生成（照片加原来那张对标原图，提示词只改说到的地方），不接着上一次的生图对话改，改出来的图不糊；批注图只给 AI 看位置，不交给生图（上面画着标记）。
- 学员版做完封面要改选题总览、选题卡、重新生成工作台数据：开源版工作台从文件现算（仓库规矩第 1 条），这些都不做。

### 为什么自己读设置，不直接用调研 Skill 的 research_kit

- `cover_kit/places.py` 照创作页 `creation_doc.py` 和调研 Skill 的做法另写一份小的，读同一个设置文件，没 import 调研 Skill 的 `research_kit/places.py`：那份不认 `coverAssets` 和端口，报错是它自己的错误类型；而且两个 Skill 的文件夹名都跟着品牌 id 走，互相 import 要拼另一个 Skill 的路径，用复制装法装 Skill 时还找不到。默认位置、端口和本机常见服务占用的端口由 `tests/cover-skill.test.mjs` 和 `lib/config.mjs`、`lib/ports.mjs` 对齐。
- 工作台在不在运行：和 `pnpm start` 一样从界面端口往后问 `/api/health`，只认同一个设置文件起的那一份（app 和 instance 都对上），用它报的界面端口拼详情页链接 `http://127.0.0.1:<端口>/content/<编号>`；连本机端口被拒绝时说「查不了」，不说「没在运行」。
- 下载封面用自己的几行（只下 https，http 只认本机地址给测试用；最大 20 MB；扩展名按文件头）：调研 Skill 的 `download_image` 下载失败一律返回空，分不出链接过期和连不上网。
